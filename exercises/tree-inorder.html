Trees: Inorder Traversal

Trees (Binary) Beginner
Prerequisites
  • #53 preorder traversal — Root-Left-Right

What's New Here

Preorder visits the root first. Inorder visits the root between its children: Left → Root → Right. The crucial insight: for a Binary Search Tree (BST), inorder traversal produces nodes in sorted order. This makes inorder the most important traversal for BSTs.

Why Inorder?

Use Cases

BST → sorted output: Inorder traversal of a BST gives you all elements in ascending order, for free.

BST validation: If inorder output isn't sorted, the tree isn't a valid BST.

Infix notation: Expression trees in inorder give infix notation: 2 + 3.

Kth smallest: Inorder traversal to the kth node gives the kth smallest element in a BST.

The Algorithm

How It Works

1. Recurse on the left subtree.
2. Visit the current node (add to output).
3. Recurse on the right subtree.
The only difference from preorder: move the visit call to between the two recursive calls.

Time & Space Complexity

Time: O(n) — every node visited once.

Space: O(h) — recursion depth = tree height.

Pseudocode

function inorder(node):
    if node is null:
        return
    inorder(node.left)       // left subtree first
    visit(node)              // process BETWEEN children
    inorder(node.right)      // right subtree last

Walkthrough

BST [4, 2, 6, 1, 3, 5, 7]

        4
       / \
      2   6
     / \ / \
    1  3 5  7

Inorder: go left from 4
  go left from 2
    visit(1), back to 2
  visit(2), go right
    visit(3), back to 2, back to 4
visit(4), go right from 4
  go left from 6
    visit(5), back to 6
  visit(6), go right
    visit(7)

Output: [1, 2, 3, 4, 5, 6, 7] ← SORTED!

Common Pitfalls

1. Assuming inorder always gives sorted output

It only gives sorted output for BSTs. For a general binary tree, the output reflects the structure but has no sorted guarantee.

All Three Traversals Compared

Same tree, different visit order

Preorder (Root-Left-Right): [4, 2, 1, 3, 6, 5, 7] — good for copying.

Inorder (Left-Root-Right): [1, 2, 3, 4, 5, 6, 7] — sorted for BSTs.

Postorder (Left-Right-Root): [1, 3, 2, 5, 7, 6, 4] — good for deletion.

All three use the same recursive structure; only the position of visit() changes.
