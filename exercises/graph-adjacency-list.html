Why Adjacency Lists?

The Problem

Graphs model relationships: social networks, road maps, dependencies, web links. To work with a graph in code, you need a data structure to represent it. The two most common representations are the adjacency matrix and the adjacency list.

Adjacency List vs. Matrix

Adjacency Matrix: V×V grid. Space: O(V²). Check edge: O(1). Good for dense graphs.

Adjacency List: Array of lists. Space: O(V+E). Iterate neighbors: O(degree). Good for sparse graphs.

Most real-world graphs are sparse (a Facebook user has ~300 friends out of 3 billion users). Adjacency lists are the default choice.

What Is an Adjacency List?

Definition

An adjacency list stores a graph as a collection of lists, one per vertex. Each vertex's list contains all the vertices it has an edge to (its neighbors).

In Python, this is typically a dict[str, list[str]] or list[list[int]] for integer-labeled vertices.

Example

Given this graph:

    A --- B
    |     |
    C --- D --- E

The adjacency list is:

{
  'A': ['B', 'C'],
  'B': ['A', 'D'],
  'C': ['A', 'D'],
  'D': ['B', 'C', 'E'],
  'E': ['D']
}

For an undirected graph, if A has B in its list, B must also have A. For a directed graph, edges are one-way.

Common Operations

Operations and Their Costs

Add vertex: O(1) — insert a new key with an empty list.

Add edge (u, v): O(1) — append v to u's list (and u to v's for undirected).

Check if edge exists: O(degree(u)) — scan u's neighbor list.

Get all neighbors: O(1) — return the list directly.

Remove edge: O(degree(u)) — find and remove v from u's list.

Pseudocode

class Graph:
    def __init__(self):
        self.adj = {}  # dict of vertex -> list of neighbors

    def add_vertex(self, v):
        if v not in self.adj:
            self.adj[v] = []

    def add_edge(self, u, v):
        self.adj[u].append(v)
        self.adj[v].append(u)  # omit for directed graph

    def neighbors(self, v):
        return self.adj[v]

    def has_edge(self, u, v):
        return v in self.adj[u]

Directed vs. Undirected

For a directed graph, add_edge(u, v) only appends v to u's list. For undirected, you do it both ways. This is the only difference in the implementation.

Weighted Graphs

For weighted edges, store tuples instead of plain vertices: adj['A'] = [('B', 5), ('C', 3)]. The second element is the edge weight.

Common Pitfalls

1. Forgetting the reverse edge in undirected graphs

If you add edge (A, B), you must also add (B, A). Forgetting this creates a directed graph accidentally, which will break BFS/DFS traversals.

2. Duplicate edges

The basic list representation allows duplicate edges. If you call add_edge('A', 'B') twice, B appears twice in A's list. Use a set instead of a list if duplicates are problematic.

3. Missing vertices

Adding an edge before adding the vertices causes a KeyError. Always ensure both vertices exist before adding an edge, or have add_edge create them automatically.
