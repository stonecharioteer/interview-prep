Stack: Evaluate Postfix (RPN)

Stacks Intermediate

What You Will Learn

This exercise teaches stack-based expression evaluation. You will learn the difference between operands and operators, and how postfix notation eliminates the need for parentheses entirely. This is how calculators and compilers actually evaluate expressions.

What is Postfix Notation?

Definition

In postfix (Reverse Polish Notation), the operator comes after its operands. Instead of 3 + 4 (infix), you write 3 4 +. Instead of (2 + 3) * 4, you write 2 3 + 4 *.

No parentheses are needed because the order of operations is unambiguous.

Why Use Postfix?

Real-World Use Cases

HP calculators: Classic RPN calculators used by engineers for decades.

Compilers: Compilers convert infix to postfix as an intermediate step, then evaluate.

Stack-based VMs: The Java Virtual Machine and WebAssembly use stack-based evaluation.

The Algorithm

Read tokens left to right:

If number: push it onto the stack.

If operator: pop two values, apply the operator, push the result.

At the end, the stack holds exactly one value: the answer.

Time & Space Complexity

Time: O(n) — process each token once.

Space: O(n) — stack can hold up to n/2 operands.

Pseudocode

function evaluate_postfix(tokens):
    stack = new Stack()
    operators = {'+', '-', '*', '/'}

    for each token in tokens:
        if token is a number:
            stack.push(token)
        else if token is in operators:
            b = stack.pop()    // second operand (popped first!)
            a = stack.pop()    // first operand
            result = apply(token, a, b)
            stack.push(result)

    return stack.pop()         // final answer

Walkthrough

Tracing "3 4 + 2 *" which is (3+4)*2 = 14

Token '3': number, push.          Stack: [3]
Token '4': number, push.          Stack: [3, 4]
Token '+': operator, pop 4 and 3. 3 + 4 = 7. Push 7.  Stack: [7]
Token '2': number, push.          Stack: [7, 2]
Token '*': operator, pop 2 and 7. 7 * 2 = 14. Push 14. Stack: [14]
Result: 14

Common Pitfalls

1. Operand order matters for subtraction and division

When you pop two values for - or /, the first popped value is the second operand. a b - means a - b, not b - a.

2. Invalid expressions

If you try to pop from an empty stack, the expression is malformed. A valid postfix expression always has exactly n-1 operators for n operands.

What You Learned

Key Takeaways

Operands vs operators: Numbers go on the stack; operators consume from it.

No parentheses needed: Postfix encodes precedence in token order.

Stack as accumulator: The stack holds intermediate results during computation.
