What is a Map (Dictionary)?

Definition

A map (also called dictionary, hash map, or associative array) stores key-value pairs. You give it a key, it gives you back the associated value — in O(1) average time.

Think of a real dictionary: you look up a word (the key) and get its definition (the value). You do not read every page; you jump straight to the right entry.

How It Works: Hash Functions

Under the hood, a map uses a hash function to convert the key into an array index. The hash function takes any key (a string, number, etc.) and produces an integer. That integer, modulo the array size, determines where the value is stored. 

index = hash(key) % array_size

This is why lookup is O(1) on average — you compute the index directly instead of searching through every entry.

Key Properties

Lookup: O(1) average, O(n) worst case (hash collisions).

Insert: O(1) average.

Delete: O(1) average.

Keys are unique: each key maps to exactly one value. Setting the same key again overwrites the old value.

Unordered: keys have no guaranteed order (in most implementations).

Why get_or_default?

The Problem

When you look up a key that does not exist in the map, most languages either throw an error or return a special "not found" value. The get_or_default pattern returns a fallback value you specify instead of crashing.

This is essential for the counting pattern: when counting occurrences, you want get_or_default(key, 0) so a missing key starts at 0 rather than causing an error.

Real-World Use Cases

Configuration settings: Look up a user preference; fall back to the default if not set.

Caching: Return the cached result if it exists; otherwise return a sentinel indicating "not cached."

Counting: counts[item] = get_or_default(counts, item, 0) + 1 — the foundation of frequency counting.

Feature flags: Check if a feature is enabled for a user; default to false.

Pseudocode

function get_or_default(map, key, default_value):
    if key exists in map:
        return map[key]
    else:
        return default_value

Walkthrough

Step by step

map = {"host": "localhost", "port": "8080", "debug": "true"}

get_or_default(map, "port", "3000")
  -> "port" exists -> return "8080"

get_or_default(map, "timeout", "30")
  -> "timeout" not found -> return default "30"

get_or_default(map, "debug", "false")
  -> "debug" exists -> return "true"

Common Pitfalls

1. Confusing "key not found" with "value is null"

A key can exist and map to a null/empty value. That is different from the key not existing at all. get_or_default only returns the default when the key is absent, not when the value happens to be empty.

2. Mutating the default

If the default is a mutable object (like a list), returning the same default object repeatedly can lead to shared state bugs. Always create a fresh default if it is mutable.

What You Learned

Key Takeaways

Maps store key-value pairs with O(1) average lookup via hash functions.

get_or_default safely handles missing keys without errors.

This pattern is the building block for counting, caching, and configuration.
