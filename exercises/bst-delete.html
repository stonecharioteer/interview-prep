EXERCISE #130

BST: Delete

Trees (BST) Intermediate
Prerequisites
  • #122 BST: Search — finding nodes in a BST

What You Will Learn

Delete a node from a BST while maintaining the ordering property. There are three cases, like removing a person from an org chart:

Case 1 (Leaf): No children — just remove it. Like someone with no reports.

Case 2 (One child): One child takes the deleted node's place. Like someone with one report — the report moves up.

Case 3 (Two children): Find the inorder successor (smallest in right subtree), copy its value, then delete the successor. Like finding the next-in-line to take over.

The Algorithm

Three Cases of BST Deletion

Case 1 Leaf node: Simply remove the node (set parent's pointer to null).

Case 2 One child: Replace the node with its only child.

Case 3 Two children: Find inorder successor (leftmost in right subtree), copy its value to the target node, then delete the successor (which is Case 1 or 2).

Time & Space Complexity

Time: O(h) — find the node + possibly find the successor. Both are O(h).

Space: O(h) — recursion stack depth.

Pseudocode

function delete(node, target):
    if node is null: return null
    if target < node.val:
        node.left = delete(node.left, target)
    else if target > node.val:
        node.right = delete(node.right, target)
    else:
        // Found the node to delete
        if node.left is null:       // Case 1 or 2
            return node.right
        if node.right is null:      // Case 2
            return node.left
        // Case 3: two children
        successor = findMin(node.right)
        node.val = successor.val
        node.right = delete(node.right, successor.val)
    return node

function findMin(node):
    while node.left: node = node.left
    return node

Common Pitfalls

1. Not handling all three cases

Each case requires different handling. Forgetting Case 3 (two children) is the most common mistake.

2. Confusing predecessor and successor

You can use either the inorder predecessor (rightmost in left subtree) or successor (leftmost in right subtree). Pick one and be consistent.

3. Not updating parent pointers

The recursive approach handles this naturally by returning the new subtree root. The iterative approach must explicitly update parent pointers.

What You Learned

Key Takeaways

Three cases, increasing complexity: leaf (trivial), one child (replace), two children (find successor).

Inorder successor preserves BST property: it is the smallest value larger than the deleted node.

Deletion reduces to simpler cases: Case 3 copies a value then deletes a leaf or one-child node.
