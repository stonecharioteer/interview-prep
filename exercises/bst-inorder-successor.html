BST: Inorder Successor

Trees (BST) Intermediate
Prerequisites
  • #59 Inorder Traversal — visiting nodes in sorted order
  • #122 BST: Search — navigating a BST

What You Will Learn

Find the inorder successor of a node — the next node in sorted order. The question is: "who comes next?"

Case 1: If the node has a right subtree, the successor is the leftmost node in that subtree (the smallest thing to your right).

Case 2: If no right subtree, walk up from the root to find the first ancestor where the target is in the left subtree.

The Algorithm

Two Cases

Case 1 (Has right subtree): Go right once, then go left as far as possible. That is the successor.

Case 2 (No right subtree): Start from the root. Whenever you go left (target < node), update the successor candidate to the current node. The last such candidate is the answer.

Time & Space Complexity

Time: O(h) — at most traverse the height of the tree.

Space: O(1) — iterative approach uses no extra space.

Pseudocode

function inorderSuccessor(root, target):
    successor = null
    node = root
    while node:
        if target < node.val:
            successor = node   // candidate!
            node = node.left
        else:
            node = node.right
    return successor

// Note: if target has right subtree,
// this naturally finds leftmost in right subtree.
// If not, it finds the deepest ancestor where
// target is in the left subtree.

Walkthrough

Case 1: Successor of 3 in BST [8, 3, 10, 1, 6, 4, 14]

        8
       / \
      3   10
     / \    \
    1   6   14
       /
      4

Inorder: 1, 3, 4, 6, 8, 10, 14
Successor of 3: node 3 has a right subtree (rooted at 6).
  Go right to 6, then left to 4.
  4 has no left child. Successor = 4.

Case 2: Successor of 6

Node 6 has no right subtree.
Walk from root, tracking last left turn:
  At 8: 6 < 8 → candidate = 8, go left
  At 3: 6 > 3 → go right
  At 6: found target.
Last candidate = 8. Successor = 8.

Common Pitfalls

1. Forgetting the no-right-subtree case

If the node has no right subtree, the successor is NOT in its subtree at all. You must look at ancestors.

2. Not handling the largest node

The largest node in the BST has no successor. Return null.

What You Learned

Key Takeaways

Two cases based on right subtree existence: either find the minimum in the right subtree, or find the nearest ancestor where you are on the left side.

The unified iterative approach works for both: walk from root, update candidate on every left turn.

Used in BST deletion: Case 3 of delete uses inorder successor to replace the deleted node.
