Heap: Peek & Size

Heaps Beginner
Prerequisites
  • #60 Heap: Define — understanding heap structure
  • #67 Heap: Min Insert

What You Will Learn

How peek() returns the minimum (or maximum) element in O(1) by simply reading the root, and how size() returns the element count in O(1) by reading the array length. You will contrast these with extract_min() which is O(log n) because it must restore the heap property.

The Operations

Definition

peek(): Return the root element (minimum in a min-heap) without removing it. O(1).

size(): Return the number of elements in the heap. O(1).

extract_min() (for contrast): Remove and return the root, then sift down to restore the heap. O(log n).

Why O(1)?

Key Insight

A heap is stored as an array. The root is always at index 0. Reading arr[0] is O(1). The size is simply the length of the array, also O(1). No traversal needed.

Think of the conference hall: peek() is just looking at who's in the very front seat — you don't need to check any other row. size() is counting how many seats are occupied. Both are instant.

In contrast, extract_min removes the root, moves the last element up, and sifts it down through up to log n levels to find its correct position.

Pseudocode

class MinHeap:
    def __init__(self):
        self.data = []

    def peek(self):
        if len(self.data) == 0:
            return None
        return self.data[0]      # O(1) — just read index 0

    def size(self):
        return len(self.data)    # O(1) — just return length

    def extract_min(self):
        if len(self.data) == 0:
            return None
        min_val = self.data[0]
        self.data[0] = self.data[-1]
        self.data.pop()
        self._sift_down(0)       # O(log n) — restore heap
        return min_val

Common Pitfalls

1. Confusing peek with extract

peek() does NOT remove the element. extract_min() does. If you only need to read the min, use peek to avoid the O(log n) cost.

2. Peeking an empty heap

Always check size() > 0 before peeking. An empty heap has no root to return.

What You Learned

Key Takeaways

peek and size are O(1) because they just read from the underlying array without modifying structure.

extract is O(log n) because removing the root requires restoring the heap property via sift-down.
