The Problem

Definition

Given a prefix, return all words in the trie that start with that prefix. This is the core operation behind every autocomplete system.

Mental Model: GPS Street Search

Like a GPS navigation system: you type the first few characters of a street name, and the GPS shows all matching streets. The trie is the map, the prefix is your partial input, and the autocomplete results are all streets that match.

The trie lets you narrow down millions of possibilities to a handful in O(prefix_length + results) time.

How It Works

Two-Phase Algorithm

Phase 1 — Navigate to the prefix node: Walk the trie character by character. If the prefix doesn't exist, return an empty list.

Phase 2 — Collect all words via DFS: From the prefix node, do a depth-first search. Track the current path. Every time you reach an is_end node, the path from root to here is a complete word — add it to the results.

def autocomplete(prefix):
    # Phase 1: navigate to prefix node
    node = root
    for char in prefix:
        if char not in node.children:
            return []
        node = node.children[char]

    # Phase 2: DFS to collect all words
    results = []
    def dfs(curr, path):
        if curr.is_end:
            results.append(path)
        for ch, child in sorted(curr.children.items()):
            dfs(child, path + ch)

    dfs(node, prefix)
    return results

Complexity

Time: O(p + n) where p = prefix length, n = total nodes in the subtree.

Space: O(k * m) where k = number of matching words, m = average word length.

Common Pitfalls

1. Forgetting the prefix node itself

If the prefix itself is a complete word (e.g., "app"), you must check is_end on the prefix node before DFS-ing into children. Don't skip it.

2. Unordered results

DFS order depends on how children are stored. For alphabetically sorted results, iterate children in sorted order.
