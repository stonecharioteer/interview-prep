Trie: Search for a Word

Trie Intermediate

Why Trie Search?

The Problem

You have a dictionary of words stored in a trie and need to check if a specific word exists. Unlike a hash set which gives you a yes/no answer, a trie lets you also efficiently check prefixes, making it ideal for autocomplete, spell-checking, and IP routing.

Complexity

Time: O(m) where m is the length of the search word.

Space: O(1) extra — just a pointer walking the trie.

This is independent of how many words are in the trie. Whether you have 10 words or 10 million, searching for "cat" always takes exactly 3 steps.

How Search Works

The Algorithm

Starting from the root, for each character in the search word:

  1. Check if the current node has a child for this character.
  2. If no: the word is not in the trie. Return false.
  3. If yes: move to that child node and continue.

After processing all characters, check the isEndOfWord flag on the final node. If it's true, the word exists. If false, only a prefix exists (e.g., searching "app" in a trie containing only "apple").

Search vs. StartsWith

The difference between search("app") and startsWith("app") is just the final check:

search: Walk the trie AND check isEndOfWord == true.

startsWith: Walk the trie. If you reach the end without a missing character, return true.

Walkthrough

Given a trie containing: ["cat", "car", "card", "care"]

Search "car" → true

root → 'c' (found) → 'a' (found) → 'r' (found, isEndOfWord=true)
Result: true ✓

Search "ca" → false

root → 'c' (found) → 'a' (found, isEndOfWord=false)
Result: false ✗ (prefix exists, but "ca" was never inserted as a word)

Search "dog" → false

root → 'd' (NOT found)
Result: false ✗ (no child for 'd', stop immediately)

Pseudocode

def search(word):
    node = root

    for char in word:
        if char not in node.children:
            return False
        node = node.children[char]

    return node.isEndOfWord

Why isEndOfWord Matters

Without isEndOfWord, you couldn't distinguish between "a word that was inserted" and "a prefix of some longer word." For example, if you insert "apple" but not "app", searching "app" should return false even though the path r→a→p→p exists.

Common Pitfalls

1. Forgetting the isEndOfWord check

The most common bug: returning true whenever you successfully walk all characters. You must verify the final node is marked as an end of word.

2. Case sensitivity

"Cat" and "cat" are different paths in a trie. Decide upfront whether to normalize to lowercase before inserting and searching.

3. Empty string edge case

Searching for "" should check root.isEndOfWord. This is correct if you previously inserted an empty string, but unexpected otherwise.
