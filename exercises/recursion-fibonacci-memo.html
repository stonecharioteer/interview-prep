Recursion: Fibonacci with Memoization

Recursion Beginner
Prerequisites
  • #97 Fibonacci (Naive) — the exponential call tree you are about to fix
  • #17 Factorial with Memoization — memoization basics

What You Will Learn

In the previous exercise, naive Fibonacci made 15 calls for fib(5) because it recomputed the same subproblems. Now you will add a cache (memo table). Before recursing, check the cache. If the value is there, return it immediately — a cache hit. This collapses O(2n) down to O(n).

How Memoization Fixes Fibonacci

The Idea

Keep a dictionary memo. When fib(k) is called:

1. If k is in memo, return memo[k] instantly (cache hit).

2. Otherwise, compute it recursively, store the result in memo[k], and return it.

Each unique subproblem is computed exactly once. All future requests are O(1) lookups.

Time & Space Complexity

Time: O(n) — each of the n+1 subproblems (fib(0) through fib(n)) is computed once. All other calls are O(1) cache hits.

Space: O(n) — memo table of size n+1, plus recursion stack of depth n.

Pseudocode

memo = {}

function fib(n):
    if n in memo:
        return memo[n]        // cache hit! O(1)
    if n <= 0: result = 0
    else if n == 1: result = 1
    else: result = fib(n-1) + fib(n-2)
    memo[n] = result          // store before returning
    return result

Common Pitfalls

1. Checking the cache too late

The memo check must be the first thing in the function, before any recursive calls. Otherwise you still recurse even when the answer is cached.

2. Forgetting to store the result

If you compute but do not write to the cache, you get no benefit. Always memo[n] = result before returning.

3. Not recognizing this is top-down DP

Recursion + memoization is called top-down dynamic programming. The next step is to flip it around into a bottom-up table (tabulation) — which is what we do next.

What You Learned

Key Takeaways

Memoization eliminates redundancy: From O(2n) down to O(n) by caching each unique subproblem.

Cache hits = free answers: Each green/yellow lookup saved an entire subtree of recursive calls.

Top-down DP: This is dynamic programming done recursively. Next, you will learn the bottom-up (tabulation) approach.
