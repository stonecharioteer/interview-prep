EXERCISE #28

Queue: Implement Using Two Stacks

Queue Intermediate
Prerequisites
  • #14 Stack — understanding LIFO operations
  • #15 Queue — understanding FIFO operations

What You Will Learn

This exercise teaches you how to simulate one data structure using another. You will build a queue (FIFO) using only two stacks (LIFO). This is a classic interview problem that reveals a beautiful insight: two “reverses” cancel out, giving you FIFO order from LIFO parts. Along the way you will learn amortized analysis — why an operation that is sometimes expensive can still be O(1) on average.

The Core Idea

Two Stacks = One Queue

Maintain two stacks: an inbox (for enqueue) and an outbox (for dequeue). When you enqueue, push onto the inbox. When you dequeue, pop from the outbox. If the outbox is empty, pour everything from inbox into outbox — this reverses the order, giving you FIFO access.

Why It Works

A stack reverses order: if you push 1, 2, 3 and pop all, you get 3, 2, 1. But if you push those popped elements onto a second stack and pop again, you get 1, 2, 3 — the original order. Two reverses = original order = FIFO.

Use Cases

Where This Pattern Appears

Interview classic: One of the most frequently asked data structure problems. Tests your understanding of both stacks and queues.

Functional programming: Immutable (persistent) queues in languages like Haskell and Clojure use exactly this two-list technique.

Amortized analysis: A gateway problem for understanding why “sometimes expensive” can still be efficient on average.

Time & Space Complexity

enqueue: O(1) — always just push onto inbox.

dequeue: amortized O(1) — each element is moved at most once from inbox to outbox, so across n operations the total work is O(n).

Space: O(n) — all elements live across the two stacks.

Pseudocode

structure QueueFromTwoStacks:
    inbox  = []   // stack for enqueue
    outbox = []   // stack for dequeue

    function enqueue(value):
        inbox.push(value)

    function dequeue():
        if outbox is empty:
            while inbox is not empty:
                outbox.push(inbox.pop())   // pour inbox into outbox
        if outbox is empty:
            error "queue is empty"
        return outbox.pop()

    function peek():
        if outbox is empty:
            while inbox is not empty:
                outbox.push(inbox.pop())
        if outbox is empty:
            error "queue is empty"
        return outbox.top()

    function is_empty():
        return inbox is empty AND outbox is empty

Walkthrough

Step by step: enqueue 1, 2, 3, dequeue, enqueue 4, dequeue

enqueue(1): inbox=[1]       outbox=[]
enqueue(2): inbox=[1,2]     outbox=[]
enqueue(3): inbox=[1,2,3]   outbox=[]

dequeue():
  outbox is empty, so pour inbox into outbox:
    pop 3 from inbox, push to outbox
    pop 2 from inbox, push to outbox
    pop 1 from inbox, push to outbox
  inbox=[]  outbox=[3,2,1]
  pop from outbox: returns 1
  inbox=[]  outbox=[3,2]

enqueue(4): inbox=[4]       outbox=[3,2]

dequeue():
  outbox is NOT empty, so just pop
  pop from outbox: returns 2
  inbox=[4]  outbox=[3]

Each element moves from inbox to outbox exactly once, so amortized cost per operation is O(1).

Common Pitfalls

1. Transferring too often

Only pour inbox into outbox when outbox is empty. If you transfer on every dequeue, you break the order and lose amortized efficiency.

2. Forgetting to check both stacks for emptiness

The queue is empty only when both inbox and outbox are empty. Checking just one gives wrong results.

3. Confusing worst-case with amortized

A single dequeue can take O(n) if it triggers a pour. But across n operations, each element is poured at most once, so the total is O(n) — amortized O(1) per operation.

What You Learned

Key Takeaways

Simulation: You can build one data structure from another. Two stacks can simulate a queue.

Amortized O(1): An operation can be expensive sometimes but cheap on average. The key insight is that each element is transferred at most once.

Two reverses cancel out: Stack reverses order; two stacks restore original order, giving FIFO from LIFO.
