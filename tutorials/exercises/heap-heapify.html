Heapify: Build a Heap from an Array

Heap Intermediate
Required Learning

The Problem

You Have an Array. You Want a Heap.

Given an unsorted array of n elements, rearrange it so it satisfies the heap property. The naïve approach: insert elements one at a time using insert(). Each insert is O(log n), so total is O(n log n).

But there's a faster way. The bottom-up heapify algorithm does it in O(n) — and the reason is beautifully counterintuitive.

Conference Hall: The Efficient Approach

Everyone Sits Randomly, Then We Fix It

Imagine 15 people walk into the conference hall and sit in random seats. Instead of seating them one by one (the insert approach), we let everyone sit wherever they want, then fix the seating from the back rows forward.

Key insight: The last row (the leaves) is already valid — they have no one behind them to compare against. So we start at the second-to-last row and work forward:

  1. For each person in row 3, check if they're shorter than the two behind them. If not, swap.
  2. Move to row 2 and repeat.
  3. Move to row 1 and repeat.
  4. Finally fix the front row (root).

Each person only needs to "bubble down" through the rows behind them. People in the back rows barely move (1-2 swaps at most). Only the person at the very front might traverse the entire hall. Since most people sit in the back rows, most fixes are cheap.

Why O(n), Not O(n log n)?

The Math That Makes It Beautiful

In a heap with n elements and height h = log2(n):

  • n/2 nodes are leaves — they do 0 work
  • n/4 nodes are at height 1 — each does at most 1 swap
  • n/8 nodes are at height 2 — each does at most 2 swaps
  • ... and so on ...
  • 1 node (the root) is at height h — does at most h swaps

Total work = n/4 × 1 + n/8 × 2 + n/16 × 3 + ... + 1 × h

This sum converges to O(n). The key: the vast majority of nodes (near the bottom) do very little work. The few nodes that do a lot of work (near the top) are exponentially rare.

Contrast with Repeated Insert

Repeated insert() bubbles up. Leaves (the majority) might bubble all the way to the root — lots of work for the most common case.

Heapify bubbles down. Leaves do nothing. Only the root does max work — but there's only one root. Bottom-up heapify is optimal because it does the most work on the fewest nodes.

Real-World Use Cases

Error Log Batch Import

Your monitoring system boots up and loads 100,000 historical error logs from a database. Rather than inserting them one at a time into the priority queue (O(n log n) = ~1.7 million operations), you dump them all into an array and heapify in O(n) = ~100,000 operations. 17x faster.

Rate Limiter Cold Start

When a rate limiter restarts, it may need to rebuild its heap of active request windows from a snapshot. Heapify lets it come back online in O(n) instead of O(n log n).

The Algorithm

def heapify(arr):
    n = len(arr)
    # Start from the last non-leaf node and work backwards
    # Last non-leaf = parent of last element = (n - 2) // 2
    for i in range(n // 2 - 1, -1, -1):
        sift_down(arr, i, n)

def sift_down(arr, i, n):
    while True:
        left  = 2 * i + 1
        right = 2 * i + 2
        smallest = i

        if left < n and arr[left] < arr[smallest]:
            smallest = left
        if right < n and arr[right] < arr[smallest]:
            smallest = right

        if smallest == i:
            break
        swap(arr[i], arr[smallest])
        i = smallest

Why Start at (n//2 - 1)?

The last non-leaf node is the parent of the last element. Any node at index ≥ n/2 is a leaf — it has no children, so it trivially satisfies the heap property. We skip all leaves and start fixing from the first node that actually has children.

Walkthrough

Heapify [20, 15, 8, 10, 5, 25, 12]:

Step 1: Process index 2 (value 8)

Children: 25 (idx 5), 12 (idx 6). 8 < both children → no swap needed.

Step 2: Process index 1 (value 15)

Children: 10 (idx 3), 5 (idx 4). Smaller child = 5. 15 > 5 → swap.

Array: [20, 5, 8, 10, 15, 25, 12]

15 is now at index 4 (a leaf). No more children → stop.

Step 3: Process index 0 (value 20)

Children: 5 (idx 1), 8 (idx 2). Smaller child = 5. 20 > 5 → swap.

Array: [5, 20, 8, 10, 15, 25, 12]

20 is now at index 1. Children: 10 (idx 3), 15 (idx 4). Smaller = 10. 20 > 10 → swap.

Array: [5, 10, 8, 20, 15, 25, 12]

20 is now at index 3 (a leaf). Done!

Final Result

Array: [5, 10, 8, 20, 15, 25, 12]
Tree:        (5)
           /     \
         (10)    (8)
         /  \    /  \
       (20)(15)(25)(12)

Valid min-heap! Root is 5 (the minimum). Every parent ≤ its children.

Common Pitfalls

1. Starting from the wrong index

Start at n//2 - 1, not n-1. Starting from the last element wastes time processing leaves that don't need fixing.

2. Using bubble-up instead of bubble-down

Heapify uses sift_down, not sift_up. Using sift-up from the beginning would give you O(n log n), losing the efficiency advantage.

3. Confusing heapify with repeated insert

heapify rearranges an existing array in-place. Repeated insert() builds a new heap from scratch. Both produce valid heaps, but heapify is asymptotically faster.
