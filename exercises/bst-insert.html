BST: Insert

Trees (BST) Beginner
Prerequisites
  • #45 Define Binary Tree Node — tree node structure
  • #37 Binary Search — the halving principle

What You Will Learn

Insert a new value into a Binary Search Tree while maintaining the BST ordering property: every node in the left subtree is smaller, every node in the right subtree is larger. Think of it like filing a document — at each folder level, you compare and decide whether to go left or right until you find the empty slot where the new value belongs.

The Algorithm

How It Works

1. Start at the root.

2. Compare the new value with the current node.

3. If new value < current, go left. If new value > current, go right.

4. When you reach a null child, that is the insertion point. Create the new node there.

The path you travel is at most the height of the tree.

Time & Space Complexity

Time: O(h) — where h = height. O(log n) for balanced BSTs, O(n) for skewed trees.

Space: O(h) — recursion stack (or O(1) for iterative).

Pseudocode

function insert(node, value):
    if node is null:
        return new Node(value)
    if value < node.val:
        node.left = insert(node.left, value)
    else if value > node.val:
        node.right = insert(node.right, value)
    return node

Walkthrough

Insert 5:

  At 3: 5 > 3 → go right
  At 6: 5 < 6 → go left

Common Pitfalls

1. Forgetting to return the node

The recursive insert must return the (possibly new) subtree root back to the parent. Without return node, the tree structure is lost.

2. Handling duplicates

Decide upfront: do you allow duplicates? Common choices: skip them, put equal values on the left, or count occurrences. The standard approach skips duplicates.

3. Insertion order determines shape

Inserting sorted data creates a skewed tree (like a linked list), giving O(n) operations. This is why balanced BSTs (AVL, Red-Black) exist.

What You Learned

Key Takeaways

BST insert follows the ordering property: compare at each node, go left or right, insert at the null slot.

Same halving idea as binary search: each comparison eliminates half the remaining tree.

Tree shape depends on insertion order: random order gives roughly balanced trees; sorted order gives worst-case skewed trees.
