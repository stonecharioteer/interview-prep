Why Heap Sort?

The Problem Heap Sort Solves

You need a comparison-based sort that is guaranteed O(n log n) in the worst case, unlike quicksort which can degrade to O(n²). Heap sort also sorts in-place using O(1) extra space, unlike merge sort which needs O(n).

Complexity

Time: O(n log n) — always, in all cases (best, average, worst).

Space: O(1) extra — sorting happens inside the original array.

For n = 1,000,000: roughly 20,000,000 operations vs 1,000,000,000,000 for O(n²) sorts.

How Heap Sort Works

The Two-Phase Algorithm

Phase 1 — Build a Max-Heap: Rearrange the array so it satisfies the max-heap property (every parent ≥ its children). This takes O(n) using heapify.

Phase 2 — Repeated Extraction: The max element is at index 0. Swap it with the last unsorted element, shrink the heap by one, and sift-down to restore the heap property. Repeat until the heap is empty. Each extraction is O(log n), done n times = O(n log n).

Why Max-Heap for Ascending Sort?

This is a common point of confusion. We use a max-heap (not min-heap) to sort in ascending order. The largest element gets swapped to the end of the array first, then the second-largest to the second-to-last position, and so on. The sorted portion grows from right to left.

If you used a min-heap, the minimum would be at index 0, but extracting it would require shifting all elements — losing the O(1) space advantage.

Real-World Analogy: Conference Hall Dismissal

Remember the conference hall from the min-heap tutorial? For heap sort, flip the rule: tallest people sit at the front (max-heap). To sort everyone by height:

1. Build the seating: Everyone sits down following the "taller-in-front" rule (heapify).
2. Dismiss one by one: The tallest person (front row) stands up and goes to the end of the sorted line. The person from the very last seat fills the empty front seat, then shuffles back until the seating rule is restored. Repeat. Each dismissal touches at most ~log2(n) rows.

When everyone has been dismissed, the line is sorted shortest-to-tallest — ascending order.

Walkthrough

Let's sort the array [4, 10, 3, 5, 1].

Phase 1: Build Max-Heap

Apply heapify to get: [10, 5, 3, 4, 1]

       (10)
      /     \
    (5)     (3)
   /   \
  (4)  (1)

Phase 2: Extract Max Repeatedly

Step 1: Swap 10 with 1, heap size = 4. Sift down: [5, 4, 3, 1 | 10]

Step 2: Swap 5 with 1, heap size = 3. Sift down: [4, 1, 3 | 5, 10]

Step 3: Swap 4 with 3, heap size = 2. Sift down: [3, 1 | 4, 5, 10]

Step 4: Swap 3 with 1, heap size = 1. Done: [1, 3, 4, 5, 10]

Pseudocode

def heap_sort(arr):
    n = len(arr)

    # Phase 1: Build max-heap (heapify)
    for i in range(n // 2 - 1, -1, -1):
        sift_down(arr, n, i)

    # Phase 2: Extract elements
    for end in range(n - 1, 0, -1):
        swap(arr[0], arr[end])   # Move max to sorted region
        sift_down(arr, end, 0)   # Restore heap on reduced range

def sift_down(arr, size, i):
    largest = i
    left  = 2 * i + 1
    right = 2 * i + 2

    if left < size and arr[left] > arr[largest]:
        largest = left
    if right < size and arr[right] > arr[largest]:
        largest = right

    if largest != i:
        swap(arr[i], arr[largest])
        sift_down(arr, size, largest)

Common Pitfalls

1. Using a min-heap for ascending sort

A min-heap puts the minimum at index 0, but extracting it efficiently requires a separate output array (O(n) space). Use a max-heap to sort in-place ascending.

2. Forgetting to reduce heap size after each extraction

After swapping the max to the end, the sift-down must only operate on indices 0..end-1, not the full array. The sorted tail is "frozen."

3. Not stable

Heap sort is not stable — equal elements may change their relative order. If stability matters, use merge sort.
