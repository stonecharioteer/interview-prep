Monotonic Stack: Next Greater Element

Monotonic Stack Intermediate

Why Next Greater Element?

Use Cases

Stock span problem: For each day, find how many consecutive days before it had a lower price — same pattern.

Histogram problems: Largest rectangle in a histogram uses a monotonic stack to find boundaries.

Temperature problems: "How many days until a warmer temperature?" is next-greater-element in disguise.

What New Concept Does This Teach?

This exercise introduces the monotonic stack pattern: maintain a stack where elements are always in decreasing (or increasing) order. When a new element breaks the monotonic property, pop elements and resolve their answers. Each element is pushed and popped at most once, giving O(n) total time despite the inner while-loop.

How It Works

The Algorithm

Traverse right to left (or left to right, pushing indices).

For each element: pop stack elements that are ≤ current element (they cannot be the "next greater" for anyone).

Stack top (if non-empty) is the next greater element for the current element.

Push the current element onto the stack.

If stack is empty when checking, the answer is -1 (no greater element to the right).

Time & Space Complexity

Time: O(n) — each element is pushed once and popped at most once. Total operations ≤ 2n.

Space: O(n) — the stack can hold up to n elements in worst case (decreasing array).

Pseudocode

function next_greater_element(arr):
    n = length(arr)
    result = array of n elements, all -1
    stack = empty stack   // will hold values

    for i = n - 1 down to 0:
        // Pop elements that are not greater
        while stack is not empty and stack.top() <= arr[i]:
            stack.pop()

        // Stack top is the next greater element
        if stack is not empty:
            result[i] = stack.top()

        stack.push(arr[i])

    return result

Walkthrough

Finding next greater elements for [4, 5, 2, 10, 8]:

Right-to-left scan

i=4: val=8,  stack=[]       → result[4]=-1,  push 8.  stack=[8]
i=3: val=10, stack=[8]      → pop 8 (8≤10). stack=[]. result[3]=-1, push 10. stack=[10]
i=2: val=2,  stack=[10]     → 10>2. result[2]=10, push 2. stack=[10,2]
i=1: val=5,  stack=[10,2]   → pop 2 (2≤5). 10>5. result[1]=10, push 5. stack=[10,5]
i=0: val=4,  stack=[10,5]   → 5>4. result[0]=5, push 4. stack=[10,5,4]

Result: [5, 10, 10, -1, -1]

Common Pitfalls

1. Using < instead of ≤ when popping

If you use < instead of ≤, equal elements are kept on the stack. The problem usually asks for strictly greater, so pop elements that are equal too.

2. Confusing indices vs values on the stack

You can push either values or indices. Pushing indices is more flexible (you can look up the value and compute distances), but be consistent.

What You Learned

Key Takeaways

Monotonic stack maintains a sorted invariant and resolves answers when the invariant breaks.

O(n) amortized — the inner while-loop looks expensive but each element is pushed/popped at most once.

Pattern family: next greater, next smaller, previous greater, previous smaller — all use the same technique with minor tweaks.
