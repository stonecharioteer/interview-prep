Linked Lists: Find a Value

Linked Lists Beginner
Prerequisites
  • #7 length — linked list traversal basics

New Concept: Sequential Search (No Random Access)

In an array, you could (if sorted) use binary search to find a value in O(log n). But a linked list has no random access — you cannot jump to the middle. You must check nodes one at a time from the head, making linear search the only option.

This is the fundamental tradeoff: linked lists trade fast lookup for fast insertion/deletion.

Why Search a Linked List?

Use Cases

Membership check: Does this element exist in our dynamic collection?

Pre-condition for mutation: Before removing a value, you need to find it first.

Symbol tables: Simple implementations use linked lists for chaining (hash table collision resolution).

The Algorithm

How It Works

Walk from head to null. At each node, compare the value to the target. If it matches, return true (or the node). If you reach null without a match, return false.

Time & Space Complexity

Time: O(n) — worst case, the target is last or absent.

Space: O(1) — no extra storage.

Speed

Pseudocode

function find(head, target):
    curr = head
    while curr is not null:
        if curr.value == target:
            return true
        curr = curr.next
    return false

Common Pitfalls

1. Not handling empty list

If head is null, the loop never runs and you correctly return false. No special case needed.

2. Continuing after finding

Return immediately when found — no need to scan the rest of the list.

What You Learned

Key Takeaways

Sequential search is the only option on a linked list — no binary search possible.

Early exit when found improves average case but worst case remains O(n).

The traversal pattern (while curr is not null) is identical to length — just with a condition check inside.
