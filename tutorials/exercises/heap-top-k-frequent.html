Heap: Top K Frequent Elements

Heap Intermediate
Prerequisites
  • #113 Kth Largest Element — min-heap of size k for filtering
  • #51 Maps: Increment Count — building frequency maps

What You Will Learn

Given an array of integers, find the k most frequently occurring elements. This is a two-phase problem:

Phase 1: Build a frequency map (hash map counting occurrences).

Phase 2: Use a min-heap of size k to find the top k entries by frequency — the same bouncer pattern from Kth Largest, but now filtering by count rather than value.

The Algorithm

How It Works

1. Phase 1: Scan the array and build a frequency map: element → count.

2. Phase 2: For each entry (element, count) in the frequency map:

   a. If the heap has fewer than k entries, push it.

   b. Else if count > heap root's count, pop root and push new entry.

   c. Else discard.

3. The k entries remaining in the heap are the top k frequent elements.

Time & Space Complexity

Time: O(n + m log k) — n to build frequency map, m (unique elements) heap operations of O(log k) each.

Space: O(n + k) — frequency map + heap.

Pseudocode

function topKFrequent(arr, k):
    // Phase 1: Build frequency map
    freq = {}
    for val in arr:
        freq[val] = freq.get(val, 0) + 1

    // Phase 2: Min-heap of size k (by frequency)
    heap = new MinHeap()  // ordered by count
    for (elem, count) in freq.items():
        if heap.size < k:
            heap.push( (count, elem) )
        else if count > heap.peek().count:
            heap.pop()
            heap.push( (count, elem) )

    return [item.elem for item in heap]

Common Pitfalls

1. Comparing elements instead of frequencies

The heap must compare by frequency count, not by element value. You're looking for the most frequent, not the largest values.

2. Returning frequencies instead of elements

The answer is the elements themselves (e.g., [1, 3]), not their counts (e.g., [3, 4]). Store (count, element) pairs in the heap but return only the elements.

3. Using a max-heap of all entries

A max-heap containing all m unique entries and extracting k times is O(m + k log m). The min-heap approach is O(m log k), which is better when k is small.

What You Learned

Key Takeaways

Two-phase pattern: Build a summary (frequency map), then filter the summary (heap).

Same bouncer from Kth Largest: The heap keeps the top k by frequency. The root is the weakest member.

Composable techniques: Hash maps + heaps combine to solve problems neither can solve alone.
