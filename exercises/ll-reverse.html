New Concept: The Three-Pointer Technique

Reversing a linked list means making every node point to its predecessor instead of its successor. This requires three pointers:

prev — the node that will become curr's new "next" (starts as null).
curr — the node currently being processed.
next_temp — saves curr.next before we overwrite it, so we don't lose the rest of the list.

At each step: save next, reverse the pointer, advance prev and curr. When curr reaches null, prev is the new head.

Why This Is a Classic Interview Problem

It tests pointer manipulation under pressure. You must carefully manage three pointers without losing references.

It appears as a subproblem in many harder problems: reverse a sublist, palindrome check, reorder list, etc.

Use Cases

Undoing a sequence: Reverse a list of operations to replay them in opposite order.

Palindrome check: Reverse the second half of a linked list and compare with the first half.

Reversing a polynomial's terms: Reorder terms stored in a linked list from lowest to highest degree or vice versa.

Time & Space Complexity

Time: O(n) — single pass through the list.

Space: O(1) — three pointer variables, no extra data structures.

Walkthrough

Reversing [1, 2, 3, 4, 5]:

Step by step

Initial: prev=null, curr=1, list: 1->2->3->4->5->null

Step 1: next_temp=2, set 1.next=null(prev), prev=1, curr=2
        Reversed so far: 1->null
        Remaining: 2->3->4->5->null

Step 2: next_temp=3, set 2.next=1(prev), prev=2, curr=3
        Reversed so far: 2->1->null
        Remaining: 3->4->5->null

Step 3: next_temp=4, set 3.next=2(prev), prev=3, curr=4
        Reversed so far: 3->2->1->null
        Remaining: 4->5->null

Step 4: next_temp=5, set 4.next=3(prev), prev=4, curr=5
        Reversed so far: 4->3->2->1->null
        Remaining: 5->null

Step 5: next_temp=null, set 5.next=4(prev), prev=5, curr=null
        Reversed: 5->4->3->2->1->null

curr is null. prev (5) is the new head.

Pseudocode

function reverse(head):
    prev = null
    curr = head
    while curr is not null:
        next_temp = curr.next    // save next
        curr.next = prev         // reverse the link
        prev = curr              // advance prev
        curr = next_temp         // advance curr
    return prev                  // prev is the new head

Common Pitfalls

1. Losing the next reference

You MUST save curr.next before overwriting it. Without next_temp, you lose the rest of the list.

2. Returning curr instead of prev

When the loop ends, curr is null. The new head is prev.

3. Empty or single-node list

Both work correctly: the loop either never runs or runs once. No special cases needed.

What You Learned

Key Takeaways

The three-pointer technique (prev/curr/next_temp) is the standard pattern for in-place reversal.

Save before overwrite is a general principle whenever you modify pointers or values in place.

Reversal is a building block for harder problems: reverse k-groups, palindrome lists, reorder lists.

This completes the core linked list operations. You now know how to traverse, search, insert, remove, and reverse.
