Permutations vs. Combinations

The Key Difference

Permutations: order matters. [1,2] and [2,1] are different.

Combinations: order does not matter. {1,2} and {2,1} are the same. We only care about which elements are chosen, not their arrangement.

Choose k items from n: there are C(n,k) = n! / (k!(n-k)!) combinations. For n=5, k=2: C(5,2) = 10 combinations vs 20 permutations.

Complexity

Time: O(C(n,k)) — we generate exactly C(n,k) combinations.

Space: O(k) for the recursion stack depth.

How It Works

The Trick: Always Go Forward

To avoid generating duplicates like [1,2] and [2,1], we enforce a rule: only consider elements after the last chosen element. If we chose element at index 2, the next choice starts from index 3.

This is the key difference from permutations, where we can pick any unused element. In combinations, we always move forward through the array.

Pruning: Stop Early

If we need k elements total and have chosen len(current) so far, we need k - len(current) more. If there aren't enough elements remaining (i.e., n - start < k - len(current)), we can prune this branch entirely. This avoids exploring dead-end paths.

Result: [1,2], [1,3], [1,4], [2,3], [2,4], [3,4]  (6 combinations = C(4,2))

Pseudocode

def generate_combinations(n, k):
    result = []

    def backtrack(start, current):
        if len(current) == k:
            result.append(current.copy())
            return

        # Pruning: need (k - len(current)) more, only (n - start + 1) available
        for i in range(start, n + 1):
            if n - i + 1 < k - len(current):
                break  # not enough elements left

            current.append(i)       # Choose
            backtrack(i + 1, current)  # Explore (move forward only)
            current.pop()           # Unchoose

    backtrack(1, [])
    return result

Common Pitfalls

1. Using permutation logic

If you iterate from 0 (or 1) every time instead of from start, you'll generate permutations, not combinations. The start parameter enforces forward-only selection.

2. Skipping the pruning check

Without pruning, the algorithm still produces correct results but explores many dead-end branches. For large n, pruning is essential for performance.

3. Off-by-one in range boundaries

If elements are 1-indexed, range is range(start, n+1). If 0-indexed, it's range(start, n). Be consistent.
