New Concept: Algorithms Transfer Across Data Structures

You already learned how to find the minimum of an array: initialize with the first element, scan everything, update when smaller. The exact same algorithm works on a linked list. Only the iteration mechanism changes — instead of arr[i], you follow curr.next.

This is a powerful insight: algorithms are independent of data structures. The scan pattern transfers directly. Learning to separate "what I'm doing" from "what I'm doing it to" is a key skill.

Why Find Min on a Linked List?

Use Cases

Priority tracking: Finding the highest-priority item without maintaining a sorted structure or heap.

Simple scheduling: Finding the earliest deadline in a dynamically changing task list.

Data validation: Checking bounds on a stream of values stored as a linked list.

Time & Space Complexity

Time: O(n) — must visit every node (minimum could be the last one).

Space: O(1) — one variable to track the current minimum.

Pseudocode

function min(head):
    if head is null:
        error "empty list"
    current_min = head.value
    curr = head.next
    while curr is not null:
        if curr.value < current_min:
            current_min = curr.value
        curr = curr.next
    return current_min

What You Learned

Key Takeaways

The linear scan pattern from arrays works identically on linked lists.

Algorithms transfer across data structures — only the iteration mechanism changes.

Compare this code to the array version: the logic is the same, only arr[i] becomes curr.value and i++ becomes curr = curr.next.
