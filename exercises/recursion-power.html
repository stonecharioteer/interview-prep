Recursion: Power(base, exp)

Recursion Intermediate
Prerequisites
  • #16 factorial — basic recursion (base case + recursive case)

What's New Here

Factorial recurses linearly: n calls for n!. But power can do much better. The key insight: xn = (xn/2)². Instead of n multiplications, we only need O(log n). This is your first encounter with logarithmic recursion — the idea that halving the problem each step gives exponential speedup.

Big O: Why This Matters

Naive vs. Fast Exponentiation

Naive approach: multiply x by itself n times. That's O(n) multiplications. For power(2, 1000), that's 1000 multiplications.

Fast exponentiation (this exercise): split the exponent in half each time. power(2, 1000) → power(2, 500) → power(2, 250) → ... only ~10 steps! That's O(log n).

The pattern: whenever you can halve the problem size each step, you get O(log n) — the same principle behind binary search.

Why Learn This?

Use Cases

Cryptography: RSA encryption requires computing ab mod m for very large numbers. Fast exponentiation makes this feasible.

Scientific computing: Computing large powers efficiently in simulations and numerical methods.

Competitive programming: Many problems require modular exponentiation.

Understanding O(log n): This is the same halving principle used in binary search, merge sort's divide step, and balanced trees.

The Algorithm

Exponentiation by Squaring

Base case: x0 = 1
Even exponent: xn = (xn/2)²
Odd exponent: xn = x × xn-1 (then the exponent becomes even)

Time & Space Complexity

Time: O(log n) — the exponent halves each step.

Space: O(log n) — recursion depth is log n.

Speed

Pseudocode

function power(base, exp):
    if exp == 0:
        return 1
    if exp is even:
        half = power(base, exp / 2)
        return half * half
    else:
        return base * power(base, exp - 1)

Walkthrough

Step by step: power(2, 10)

power(2, 10)  → 10 is even → half = power(2, 5)
power(2, 5)   → 5 is odd  → 2 * power(2, 4)
power(2, 4)   → 4 is even → half = power(2, 2)
power(2, 2)   → 2 is even → half = power(2, 1)
power(2, 1)   → 1 is odd  → 2 * power(2, 0)
power(2, 0)   → base case → return 1

Unwinding:
power(2, 0)  = 1
power(2, 1)  = 2 * 1 = 2
power(2, 2)  = 2 * 2 = 4
power(2, 4)  = 4 * 4 = 16
power(2, 5)  = 2 * 16 = 32
power(2, 10) = 32 * 32 = 1024

Comparing Approaches

Naive O(n) vs. Fast O(log n)

For power(2, 1000000):
Naive: 1,000,000 multiplications
Fast: ~20 multiplications
That's a 50,000x speedup! This gap grows exponentially as n increases.

Common Pitfalls

1. Forgetting to square, not just recurse

The key optimization is half * half. If you write power(base, exp/2) * power(base, exp/2), you call the function twice and lose the O(log n) benefit — it becomes O(n) again!

2. Integer division for odd exponents

When exp is odd, subtract 1 first (making it even), then handle it. Don't use integer division on odd numbers directly.

What You Learned

Key Takeaways

Halving = O(log n): Any time you can cut the problem in half each step, you get logarithmic time.

Store intermediate results: Computing half once and squaring is key — calling the function twice destroys the speedup.

Same principle as binary search: O(log n) appears whenever we halve the search/problem space.
