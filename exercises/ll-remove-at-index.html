Linked Lists: Remove at Index

Linked Lists Intermediate
Prerequisites
  • #41 insert_at_index — navigate + splice
  • #32 remove_first — unlinking the head node

New Concept: Combining Traversal-to-Position with Node Unlinking

This is the mirror of insert_at_index. Instead of splicing in a new node, you unlink the node at position k by setting predecessor.next = target.next.

This solidifies your understanding of pointer manipulation: inserting splices a node in, removing splices a node out. Both follow the same pattern: navigate to the predecessor, then rewire next.

Use Cases

Array-like deletion from dynamic lists: When you need to delete by position rather than by value, this is the operation you reach for.

Undo buffer management: Remove an action at a specific position in a history list.

Playlist management: Remove a song at a given position in a linked playlist.

Time & Space Complexity

Time: O(n) — traverse up to n nodes to reach the target index.

Space: O(1) — constant extra space.

Pseudocode

function remove_at_index(head, index):
    if head is null:
        error "empty list"
    if index == 0:
        return head.next           // remove head
    curr = head
    for i from 0 to index - 2:
        if curr.next is null:
            error "index out of bounds"
        curr = curr.next
    if curr.next is null:
        error "index out of bounds"
    curr.next = curr.next.next     // skip over the target node
    return head

Walkthrough

Tracing remove_at_index([10, 20, 30, 40, 50], 2)

List: 10 -> 20 -> 30 -> 40 -> 50 -> null
Target index: 2 (value 30)

Step 1: index != 0, so traverse. curr = head (10), i = 0.
Step 2: i = 0 < 1 (index - 1). Move curr to 20.
Step 3: curr = 20 (predecessor). Target = curr.next = 30.
Step 4: Set curr.next = curr.next.next (40). Node 30 is unlinked.
Result: 10 -> 20 -> 40 -> 50 -> null

Common Pitfalls

1. Forgetting the head removal case

When index is 0, there is no predecessor. You must handle this separately by returning head.next.

2. Off-by-one in traversal

You need to stop at the predecessor (index - 1), not at the target itself. If you traverse to the target, you have no way to update the previous node's next pointer.

3. Not checking bounds

If the index is greater than or equal to the list length, curr.next will be null before you reach the target. Always check before dereferencing.

What You Learned

Key Takeaways

Insert and remove are mirrors: both navigate to the predecessor, then rewire one pointer.

Pointer manipulation is now a solid skill: you can add or remove nodes at any position.
