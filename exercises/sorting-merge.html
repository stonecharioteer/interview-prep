Sorting: Merge Sort

Why Merge Sort?

Use Cases

Guaranteed O(n log n): Unlike quicksort, merge sort never degrades to O(n²). Predictable performance matters in real-time systems.

External sorting: When data does not fit in memory (sorting files on disk), merge sort works naturally by merging sorted chunks.

Linked lists: Merge sort is the preferred algorithm for linked lists — it needs no random access and uses O(1) extra space on lists.

Stable sort: Equal elements keep their original order, crucial for multi-key sorting (sort by last name, then by first name).

What New Concept Does This Teach?

Merge sort teaches divide and conquer on arrays: split the problem in half, solve each half recursively, then combine the results. This is the same paradigm behind quicksort, binary search trees, and the FFT. You also learn why O(n log n) is fundamentally better than O(n²) — splitting work logarithmically instead of quadratically.

How It Works

The Algorithm

Divide: Split the array into two halves.

Conquer: Recursively sort each half.

Combine: Merge the two sorted halves into one sorted array.

Base case: an array of 0 or 1 elements is already sorted.

Time & Space Complexity

Time: O(n log n) always — the array is halved log n times, and each level does O(n) work merging.

Space: O(n) — needs a temporary array for merging. This is the main trade-off versus in-place sorts.

Pseudocode

function merge_sort(arr):
    if length(arr) <= 1:
        return arr
    mid = length(arr) / 2
    left = merge_sort(arr[0..mid])
    right = merge_sort(arr[mid..end])
    return merge(left, right)

function merge(left, right):
    result = []
    i = 0, j = 0
    while i < length(left) and j < length(right):
        if left[i] <= right[j]:
            append left[i] to result; i++
        else:
            append right[j] to result; j++
    append remaining elements from left or right
    return result

Common Pitfalls

1. Forgetting to handle remaining elements

After the main merge loop, one of the two halves may still have elements. You must append them all to the result.

2. Using < instead of ≤ in merge

Using <= (not <) when comparing left[i] to right[j] preserves stability. Equal elements from the left half come first.

What You Learned

Key Takeaways

Divide and conquer splits problems into subproblems, solves them, and combines results.

O(n log n) is the theoretical lower bound for comparison-based sorting — merge sort achieves it.

Space trade-off: Merge sort uses O(n) extra space, unlike in-place O(n²) sorts.

Stability makes merge sort safe for multi-key sorting.
