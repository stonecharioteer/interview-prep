Maps: Most Common Element

Maps Intermediate
Prerequisites
  • #51 increment_count — building frequency maps with hash maps

What's New Here

In #51 you learned to count occurrences. Now you combine two phases: Phase 1 builds a frequency map (one pass), and Phase 2 scans the map for the maximum count (second pass). The result: find the most common element in O(n) time.

Why Most Common?

Real-World Use Cases

Log analysis: Find the most frequent error code in server logs.

Voting/elections: Determine the majority candidate (plurality winner).

Web analytics: Identify the most visited page or most common user action.

Data cleaning: Find the mode to impute missing values in datasets.

The Algorithm

Two-Phase Approach

Phase 1 — Build frequency map: Scan the array. For each element, increment its count in a hash map.

Phase 2 — Find maximum: Scan the hash map entries. Track the key with the highest count.

Time & Space Complexity

Time: O(n) — one pass to build the map, one pass to find the max.

Space: O(k) — where k is the number of distinct elements (at most n).

Speed

Pseudocode

function most_common(arr):
    freq = {}
    for elem in arr:                   // Phase 1: count
        freq[elem] = freq.get(elem, 0) + 1

    max_elem = null
    max_count = 0
    for key, count in freq:            // Phase 2: find max
        if count > max_count:
            max_count = count
            max_elem = key
    return max_elem

Walkthrough

Find the most common element in [3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5]:

Step by step

Phase 1 — Build frequency map:
  {3:2, 1:2, 4:1, 5:3, 9:1, 2:1, 6:1}

Phase 2 — Scan for max:
  3:2 → max so far = 3 (count 2)
  1:2 → tied, keep 3
  4:1 → skip
  5:3 → new max! max = 5 (count 3)
  ...rest are < 3

Result: 5 appears 3 times — the most common element.

Common Pitfalls

1. Empty array

Handle the edge case: an empty array has no most common element. Return null or raise an error.

2. Ties

If multiple elements share the maximum count, this returns the first one encountered in the map scan. Clarify the problem requirements for tie-breaking.

What You Learned

Key Takeaways

Frequency map + max scan — a two-pass pattern that solves many "most/least" problems.

O(n) total — both passes are linear, so the overall algorithm is linear.

Building block — this pattern extends to top-K elements (with a heap) and more.
