Heap: Kth Largest Element in an Array

Heap Intermediate
Prerequisites
  • #60 Min-Heap: Define & Insert — insert and bubble-up
  • #67 Extract Min — extract root and sift-down

What You Will Learn

Given an unsorted array and an integer k, find the kth largest element. The trick: maintain a min-heap of size k. The heap acts as a bouncer at an exclusive club — it keeps only the k biggest values seen so far, and the root (the smallest of the k) is always the one ready to be kicked out if someone bigger arrives.

The Algorithm

How It Works

1. Create an empty min-heap.

2. For each element in the array:

   a. If the heap has fewer than k elements, insert it.

   b. Else if the element is greater than the heap root, extract the root and insert the new element.

   c. Otherwise, discard it — it is too small to be in the top k.

3. The root of the heap is the kth largest element.

The Bouncer Mental Model

Imagine a VIP room that holds exactly k people. The bouncer at the door knows who the shortest person inside is (the min-heap root). When someone new arrives:

• If the room isn't full yet, let them in.

• If they're taller than the shortest person inside, swap them — kick out the short one, let the tall one in.

• If they're shorter, turn them away.

After everyone has arrived, the shortest person still in the room is the kth tallest overall.

Time & Space Complexity

Time: O(n log k) — we process n elements, each heap operation is O(log k).

Space: O(k) — the heap holds at most k elements.

Speed

Pseudocode

function kthLargest(arr, k):
    heap = new MinHeap()
    for val in arr:
        if heap.size < k:
            heap.insert(val)
        else if val > heap.peek():
            heap.extractMin()
            heap.insert(val)
        // else: discard val
    return heap.peek()

Walkthrough

Find the 3rd largest in [3, 1, 5, 12, 2, 11, 7, 4]

Process 1:  heap=[1,3]         (room not full)
Process 5:  heap=[1,3,5]       (room full, k=3)
Process 12: 12 > 1(root), swap: heap=[3,12,5]  (kick out 1, let 12 in)
Process 2:  2 < 3(root), discard
Process 11: 11 > 3(root), swap: heap=[5,12,11] (kick out 3, let 11 in)
Process 7:  7 > 5(root), swap:  heap=[7,12,11] (kick out 5, let 7 in)
Process 4:  4 < 7(root), discard

Answer: heap root = 7 (the 3rd largest)

Common Pitfalls

1. Using a max-heap instead of a min-heap

A max-heap of size k doesn't work because the root would be the largest of the k elements, not the kth largest. You need a min-heap so the root is the smallest of the top k — which is exactly the kth largest.

2. Forgetting to check the heap size before comparing

When the heap has fewer than k elements, always insert. Don't compare against the root when the heap isn't full yet — you'd incorrectly discard elements.

3. Comparing with ≥ instead of >

If the new element equals the root, you don't need to swap. Swapping equal values wastes time and may produce wrong results if duplicates are involved.

What You Learned

Key Takeaways

Min-heap of size k = top-k filter: The heap root is always the kth largest element seen so far.

O(n log k) beats O(n log n): When k is much smaller than n, this is significantly faster than sorting.

The bouncer pattern: Keep the k best, evict the worst of the best when something better arrives.
