Heap: Kth Smallest Element in an Array

Heap Intermediate
Prerequisites
  • #113 Kth Largest Element — the mirror problem with min-heap
  • #106 Max-Heap — max-heap structure and operations

What You Will Learn

Given an unsorted array and an integer k, find the kth smallest element. This is the mirror of Kth Largest: instead of a min-heap that keeps the biggest, we use a max-heap of size k that keeps the smallest.

The max-heap root is the largest of the k smallest — which is exactly the kth smallest. Think of it as a ceiling: the heap never lets a value in that would raise the ceiling, only values that lower it.

The Algorithm

How It Works

1. Create an empty max-heap.

2. For each element in the array:

   a. If the heap has fewer than k elements, insert it.

   b. Else if the element is less than the heap root (the max), extract the root and insert the new element.

   c. Otherwise, discard it — it is too large to be in the bottom k.

3. The root of the max-heap is the kth smallest element.

The Ceiling Mental Model

Imagine a basement with room for k items. The ceiling is set by the tallest item inside (the max-heap root). When a new item arrives:

• If the room isn't full, put it in.

• If it's shorter than the ceiling, remove the tallest thing (it was too big all along) and put the shorter one in. The ceiling lowers.

• If it's taller than the ceiling, it doesn't fit — reject it.

After processing everything, the ceiling height is the kth smallest value.

Time & Space Complexity

Time: O(n log k) — n elements, each heap op is O(log k).

Space: O(k) — the heap holds at most k elements.

Speed

Pseudocode

function kthSmallest(arr, k):
    maxHeap = new MaxHeap()
    for val in arr:
        if maxHeap.size < k:
            maxHeap.insert(val)
        else if val < maxHeap.peek():
            maxHeap.extractMax()
            maxHeap.insert(val)
        // else: discard val (too big)
    return maxHeap.peek()

Walkthrough

Find the 3rd smallest in [7, 10, 4, 3, 20, 15, 2, 8]

Process 7:  heap=[7]            (room not full)
Process 10: heap=[10,7]          (room not full)
Process 4:  heap=[10,7,4]        (room full, k=3)
Process 3:  3 < 10(root), swap: heap=[7,3,4]   (kick out 10)
Process 20: 20 ≥ 7(root), discard
Process 15: 15 ≥ 7(root), discard
Process 2:  2 < 7(root), swap: heap=[4,3,2]    (kick out 7)
Process 8:  8 ≥ 4(root), discard

Answer: heap root = 4 (the 3rd smallest)

Common Pitfalls

1. Using a min-heap for kth smallest

That's backwards! A min-heap root is the smallest element, not the kth smallest. You need a max-heap so the root is the largest of the k smallest values.

2. Getting the comparison direction wrong

For kth largest, you insert when val > root. For kth smallest, you insert when val < root. The direction flips because the heap type flips.

3. Not seeing the symmetry with kth largest

These two problems are perfect mirrors. Once you understand one, you know the other. The kth smallest in an array is the same as the (n - k + 1)th largest.

What You Learned

Key Takeaways

Max-heap of size k = bottom-k filter: The root is the kth smallest.

Mirror of kth largest: Flip heap type (max instead of min) and comparison direction (< instead of >).

Same complexity: O(n log k) time, O(k) space — identical to kth largest.
