Linked Lists: Append to End

Linked Lists Beginner
Prerequisites
  • #7 length — traversal basics

New Concept: Mutation — Modifying the List

Until now, every exercise only read the list. Append is the first mutation operation: you create a new node and attach it to the end of the list.

This requires two skills: (1) traversing to find the tail (last node), and (2) setting the tail's next pointer to point at the new node.

Use Cases

Building lists incrementally: Reading data one item at a time and appending each.

Log/history: Appending events in chronological order.

Queue implementation: Enqueue at the tail (with a tail pointer, this becomes O(1)).

Time & Space Complexity

Time: O(n) — must traverse to the end to find the tail. (With a tail pointer, this becomes O(1).)

Space: O(1) — creating one new node.

Speed

Pseudocode

function append(head, value):
    new_node = create Node(value)
    if head is null:
        return new_node        // new_node becomes the head
    curr = head
    while curr.next is not null:
        curr = curr.next       // walk to the tail
    curr.next = new_node       // link the tail to new_node
    return head

Common Pitfalls

1. Empty list

If the list is empty, the new node becomes the head. Don't try to traverse a null head.

2. Forgetting to stop at the tail

The loop condition is curr.next is not null, not curr is not null. You need to stop at the last node so you can set its next.

What You Learned

Key Takeaways

Mutation means changing pointers, not just reading them.

Finding the tail requires a full traversal — O(n). A tail pointer optimization makes it O(1).

The "stop at last node" loop (while curr.next != null) is different from the "visit all" loop (while curr != null).
