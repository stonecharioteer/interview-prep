Linked Lists: Get Kth Element

New Concept: Positional Access is O(k), Not O(1)

In an array, arr[k] is instant — O(1). In a linked list, reaching position k requires walking through k nodes — O(k). This is the core tradeoff of linked lists: you sacrifice random access for dynamic sizing and cheap head insertions.

This exercise makes the tradeoff concrete: you literally count steps to reach a position.

When This Matters

If you frequently access elements by index, arrays are better. If you frequently insert/remove at the front, linked lists win.

Understanding this tradeoff helps you choose the right data structure for each problem.

Time & Space Complexity

Time: O(k) — traverse k nodes to reach position k.

Space: O(1) — one counter.

Speed

Pseudocode

function get_kth(head, k):
    curr = head
    i = 0
    while curr is not null:
        if i == k:
            return curr.value
        i = i + 1
        curr = curr.next
    error "index out of bounds"

Common Pitfalls

1. Out of bounds

If k >= length, you reach null before finding position k. Always handle this case.

2. Negative indices

Decide upfront whether you support them. Simplest: reject negative k.

What You Learned

Key Takeaways

O(k) access vs array O(1) — the fundamental linked list tradeoff.

Counting steps to a position is the building block for insert-at and remove-at operations.

Choose arrays when you need frequent positional access; linked lists when you need frequent insertion/removal.
