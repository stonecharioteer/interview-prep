EXERCISE #16

Recursion: Factorial

Recursion Beginner
Prerequisites
  • None — this is your first recursion exercise

What You Will Learn

This exercise introduces recursion — a function calling itself with a smaller input until it reaches a base case. You will see how the call stack builds up as recursive calls are made, and how return values propagate back as the stack unwinds. Factorial is the simplest and most classic example of recursion.

What is Recursion?

Definition

Recursion is when a function calls itself to solve a smaller version of the same problem. Every recursive function needs two parts:

Base case: The simplest input where the answer is known directly (no more recursion needed).

Recursive case: Break the problem into a smaller version and call the function again.

Factorial Definition

n! = n × (n-1) × (n-2) × ... × 1

Base case: 0! = 1 and 1! = 1

Recursive case: n! = n × (n-1)!

Example: 5! = 5 × 4 × 3 × 2 × 1 = 120

Use Cases

Where Recursion and Factorials Appear

Mathematical computation: Combinatorics, permutations, and probability all use factorials.

Understanding call stacks: Recursion teaches you how function calls work under the hood — each call gets its own stack frame.

Foundation for divide and conquer: Merge sort, quicksort, and binary search all use recursion to break problems into smaller pieces.

Time & Space Complexity

Time: O(n) — one recursive call per integer from n down to 1.

Space: O(n) — n frames on the call stack before unwinding begins.

Speed

Pseudocode

function factorial(n):
    if n <= 1:          // base case
        return 1
    return n * factorial(n - 1)   // recursive case

Walkthrough

Step by step: factorial(5)

Call stack builds up (each call waits for the next):
  factorial(5) calls factorial(4)
  factorial(4) calls factorial(3)
  factorial(3) calls factorial(2)
  factorial(2) calls factorial(1)
  factorial(1) returns 1          ← base case

Call stack unwinds (return values propagate back):
  factorial(2) returns 2 * 1 = 2
  factorial(3) returns 3 * 2 = 6
  factorial(4) returns 4 * 6 = 24
  factorial(5) returns 5 * 24 = 120

The stack grows to depth 5 (one frame per call), then unwinds multiplying as it goes.

Common Pitfalls

1. Missing base case

Without a base case, the function calls itself forever until you get a stack overflow. Always define when recursion stops.

2. Not shrinking toward the base case

Each recursive call must make progress toward the base case. If you call factorial(n) instead of factorial(n-1), you get infinite recursion.

3. Ignoring stack depth

For very large n, the call stack can overflow. Recursion uses O(n) space on the stack. Iterative solutions avoid this.

What You Learned

Key Takeaways

Base case + recursive case: Every recursive function needs both. The base case stops recursion; the recursive case shrinks the problem.

Call stack: Each recursive call creates a new stack frame. The stack builds up, then unwinds as returns propagate back.

O(n) time and space: Factorial recursion makes n calls, each using a stack frame.
