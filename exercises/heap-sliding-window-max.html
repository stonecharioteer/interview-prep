Heap: Sliding Window Maximum

Heap Advanced
Prerequisites
  • #106 Max-Heap — max-heap structure and operations
  • #83 Sliding Window Sum — sliding window pattern

What You Will Learn

Given an array and a window size k, find the maximum element in every contiguous window of size k as it slides from left to right.

Mental model: looking through a window that slides across the array. A max-heap always knows the tallest thing you can see. But as the window moves, some elements fall behind it — they're still in the heap but no longer in the window. We use lazy deletion: ignore the heap root if its index is outside the current window.

The Algorithm

How It Works

1. Use a max-heap storing pairs: (value, index).

2. Push the first k elements into the heap. Record heap root as the first window max.

3. For each new element (sliding the window right by 1):

   a. Push (value, index) into the heap.

   b. Lazy delete: while the heap root's index is outside the window (index ≤ current_start - 1), pop it.

   c. The heap root is the maximum for this window.

4. Return all window maximums.

Why Lazy Deletion?

Removing an arbitrary element from a heap is O(n). Instead, we leave stale elements in the heap and only remove them when they bubble up to the root. This is called lazy deletion. We only check the root — if it's outside the window, pop it and check the next root.

Time & Space Complexity

Time: O(n log n) — each element is pushed and popped at most once. Each op is O(log n).

Space: O(n) — in the worst case, no elements are lazily deleted.

Note: A monotonic deque achieves O(n) for this problem. The heap approach is simpler but slightly slower.

Pseudocode

function slidingWindowMax(arr, k):
    heap = new MaxHeap()  // stores (value, index)
    output = []

    for i in range(len(arr)):
        heap.push( (arr[i], i) )

        // Window is valid once we have k elements
        if i >= k - 1:
            // Lazy delete: remove stale roots
            while heap.peek().index <= i - k:
                heap.pop()

            output.append(heap.peek().value)

    return output

Common Pitfalls

1. Not implementing lazy deletion

Without lazy deletion, you'd need to find and remove specific elements from the heap (O(n) per removal). Lazy deletion only checks/removes from the top — much simpler.

2. Forgetting to store indices in the heap

You must store (value, index) pairs so you can check whether the root is still inside the current window. Without indices, you can't perform lazy deletion.

3. Not considering the monotonic deque alternative

A monotonic decreasing deque solves this in O(n) time and O(k) space, which is strictly better than the heap approach. The heap solution is simpler to implement but the deque is the optimal approach for interviews.

What You Learned

Key Takeaways

Lazy deletion: Leave stale entries in the heap; only remove them when they reach the root.

Heap + sliding window: The heap always knows the maximum, and lazy deletion handles window movement.

Trade-off awareness: O(n log n) with a heap vs O(n) with a monotonic deque. Know both approaches.
