Arrays: Rotate by K Positions

Arrays Intermediate
Prerequisites
  • #26 reverse_in_place — reversing an array using two pointers

What's New Here

You already know how to reverse an array in place. The three-reversal trick uses that skill three times to achieve a rotation with no extra array. The insight is surprising: reverse the whole array, then reverse the first k elements, then reverse the remaining elements. The result is a rotation by k positions — using O(1) space.

Why Rotate an Array?

Real-World Use Cases

Circular buffer rotation: Shift data in a ring buffer without copying to a new array.

Scheduling round-robin: Rotate a task queue so the next worker is at the front.

Image rotation: Row/column shifts are a building block for rotating pixel grids.

The Algorithm

How It Works (Three-Reversal Trick)

To rotate array of length n right by k positions:

• Step 1: Reverse the entire array.

• Step 2: Reverse the first k elements.

• Step 3: Reverse the remaining n − k elements.

Normalize k first: k = k % n so rotations larger than n wrap around.

Time & Space Complexity

Time: O(n) — each element is swapped at most twice across the three reversals.

Space: O(1) — all swaps are done in place.

Walkthrough

Rotate [1, 2, 3, 4, 5, 6, 7] right by k = 3:

Step by step

Original:     [1, 2, 3, 4, 5, 6, 7]

Phase 1 — Reverse entire array:
              [7, 6, 5, 4, 3, 2, 1]

Phase 2 — Reverse first k=3 elements:
              [5, 6, 7, 4, 3, 2, 1]

Phase 3 — Reverse remaining n-k=4 elements:
              [5, 6, 7, 1, 2, 3, 4]

Result: [5, 6, 7, 1, 2, 3, 4]  (rotated right by 3)

Pseudocode

function rotate_k(arr, k):
    n = len(arr)
    if n == 0:
        return
    k = k % n                    // handle k > n
    if k == 0:
        return

    reverse(arr, 0, n - 1)       // reverse entire array
    reverse(arr, 0, k - 1)       // reverse first k elements
    reverse(arr, k, n - 1)       // reverse remaining n - k elements

function reverse(arr, lo, hi):
    while lo < hi:
        swap arr[lo] and arr[hi]
        lo = lo + 1
        hi = hi - 1

Common Pitfalls

1. Forgetting to normalize k

If k ≥ n, rotating by n is a no-op. Always compute k = k % n first.

2. Off-by-one in reversal boundaries

Phase 2 reverses indices [0, k-1] and Phase 3 reverses [k, n-1]. Getting these boundaries wrong produces a garbled result.

3. Confusing left vs right rotation

The three-reversal trick as described rotates right. For left rotation by k, either rotate right by n - k, or reverse the first k, reverse the last n-k, then reverse all.

What You Learned

Key Takeaways

Three-reversal trick — an elegant O(n) time, O(1) space rotation.

Reusing reverse — a simple building block solves a harder problem.

Normalize inputs — always reduce k modulo n before processing.
