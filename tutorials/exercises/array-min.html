EXERCISE #1

Arrays: Finding the Minimum

Arrays Beginner

Starting Point

This is the very first exercise. No prerequisites needed. Everything you learn here — arrays, indexing, iteration — is the foundation for every data structure that follows.

What is an Array?

Definition

An array is an ordered, contiguous collection of elements. Each element lives at a numbered position called an index, starting from 0. You can read any element instantly by its index — arr[3] gives you the fourth element in O(1) time.

Key Properties

Indexed access: Get any element by position in constant time.

Ordered: Elements have a defined sequence — first, second, third.

Contiguous: Elements sit next to each other in memory, which makes iteration fast due to CPU cache locality.

Why Find the Minimum?

Real-World Use Cases

E-commerce: Finding the cheapest product from a list of prices.

IoT / Sensors: Finding the lowest temperature reading from a day's data.

Scheduling: Finding the earliest deadline in a task list.

Games: Finding the player with the lowest score.

This pattern — scanning through data to find an extreme value — appears everywhere. Master it here, and you'll recognize it in sorting, heaps, greedy algorithms, and more.

Introducing Big O Notation

What is Big O?

Big O notation describes how an algorithm's performance scales as input grows. It answers: "If I double the input size, how much more work does the algorithm do?"

O(1) — constant time. Same speed regardless of input size. Example: reading arr[5] takes the same time whether the array has 10 or 10 million elements.

O(n) — linear time. Work grows proportionally with input. If you double the array size, the algorithm takes roughly twice as long. Example: scanning every element to find the minimum.

Throughout these tutorials, each exercise will introduce the relevant Big O class. You'll eventually learn O(log n), O(n log n), O(n²), and more — each with a distinct visual signature you can observe in the animations.

Why Can't We Do Better Than O(n)?

For an unsorted array, the minimum could be anywhere. If you skip even one element, it might be the one holding the minimum. So you must check every element: O(n) is optimal here.

Later, you'll learn that sorted data unlocks O(log n) algorithms (binary search) and specialized structures like heaps give you O(1) access to the minimum. The data structure you choose determines what's possible.

The Algorithm: Linear Scan

How It Works

Start by assuming the first element is the minimum. Then walk through every remaining element: if it's smaller than your current minimum, update. When you've seen everything, you have the answer.

This is called a linear scan because you visit each element exactly once, in a straight line from left to right.

Time & Space Complexity

Time: O(n) — you must look at every element. There's no shortcut (the minimum could be anywhere, including the very last position).

Space: O(1) — you only track one extra variable: the current minimum.

Walkthrough

Let's trace finding the minimum of [38, 27, 43, 3, 9, 82, 10]:

Step by step

Index 0: value=38. First element, so min=38.
Index 1: value=27. 27 < 38? Yes! New min=27.
Index 2: value=43. 43 < 27? No, skip.
Index 3: value=3.  3 < 27? Yes! New min=3.
Index 4: value=9.  9 < 3?  No, skip.
Index 5: value=82. 82 < 3? No, skip.
Index 6: value=10. 10 < 3? No, skip.

Result: minimum is 3 at index 3.

Pseudocode

function min(arr):
    if arr is empty:
        error "empty array"
    current_min = arr[0]
    for i from 1 to len(arr) - 1:
        if arr[i] < current_min:
            current_min = arr[i]
    return current_min

Common Pitfalls

1. Empty array

Always check if the array is empty first. There is no minimum of nothing.

2. Starting min at 0 or infinity

Don't initialize min = 0 — what if all values are positive and larger? Don't use infinity unless you're sure the language supports it. Safest: start with arr[0].

3. Returning index vs. value

Be clear whether you need the minimum value or its index. They're different things.

What You Learned

Key Takeaways

Arrays give you O(1) access by index and O(n) search.

Linear scan is the fundamental pattern for finding things in unsorted data.

Tracking state (current min) while iterating is a pattern you'll reuse everywhere.
