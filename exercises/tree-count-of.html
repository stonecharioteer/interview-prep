Trees: Count of Value

Trees (Binary) Beginner
Prerequisites
  • #101 Contains — searching for a value in a tree

What You Will Learn

Count how many times a target value appears in a binary tree. Unlike contains which stops at the first match, this must visit every node because duplicates can appear anywhere. Watch matching nodes light up with a golden ring.

The Algorithm

How It Works

1. If the node is null, return 0 (base case).

2. If the node's value equals the target, set match = 1, else match = 0.

3. Return match + countOf(left) + countOf(right).

No short-circuiting: even after finding a match, you must search both subtrees for more.

Time & Space Complexity

Time: O(n) — must visit every node (duplicates can be anywhere).

Space: O(h) — recursion stack depth.

Speed

Pseudocode

function countOf(node, target):
    if node is null:
        return 0
    match = 1 if node.val == target else 0
    return match + countOf(node.left, target)
                 + countOf(node.right, target)

Walkthrough

Count 3 in tree [5, 3, 8, 3, 3, 7, 3]

        5
       / \
      3   8
     / \ / \
    3  3 7  3

countOf(5, 3): 5!=3, match=0
  countOf(3, 3): 3==3, match=1
    countOf(3, 3): 3==3, match=1 (left leaf)
    countOf(3, 3): 3==3, match=1 (right leaf)
    return 1 + 1 + 1 = 3
  countOf(8, 3): 8!=3, match=0
    countOf(7, 3): 7!=3, match=0
    countOf(3, 3): 3==3, match=1
    return 0 + 0 + 1 = 1
  return 0 + 3 + 1 = 4

Total count = 4

Common Pitfalls

1. Short-circuiting on first match

Unlike contains, you must NOT stop after the first match. Continue traversing both subtrees to find all occurrences.

2. Returning boolean instead of count

This returns an integer, not a boolean. Each recursive call returns how many matches it found in its subtree.

3. Forgetting to add the current node's match

A common bug: returning countOf(left) + countOf(right) without adding the current node's match value.

What You Learned

Key Takeaways

No short-circuiting: Unlike contains, you must visit every node because duplicates can appear anywhere.

Aggregate pattern: match + left_count + right_count. This is the same pattern as tree sum, but counting matches instead of summing values.

Zero for miss, one for hit: Converting a boolean match into an integer (0 or 1) lets you sum across the tree elegantly.
