Linked List: Nth Node From End

Linked Lists Intermediate
Prerequisites

What's New Here

Finding the kth element from the start is easy: advance k times. But from the end? You don't know the length in advance (no random access). The two-pointer technique solves this elegantly: advance fast by n steps first, then move both fast and slow together. When fast hits the end, slow is at the nth node from the end.

Why Two Pointers?

The Key Insight

If fast is n steps ahead of slow, and both move at the same speed, when fast reaches the end (null), slow is exactly n steps from the end. One pass, O(n), no need to compute length first.

The alternative (two passes: compute length, then advance length−n steps) also works but is less elegant.

Time & Space Complexity

Time: O(n) — single pass through the list.

Space: O(1) — two pointers only.

Walkthrough

Find 2nd node from end in [10, 20, 30, 40, 50]:

Step by step

Phase 1: Advance fast by n=2 steps.
  fast = 10 → 20 → 30.  slow = 10.

Phase 2: Move both until fast reaches null.
  fast = 40, slow = 20
  fast = 50, slow = 30
  fast = null, slow = 40

slow is at node 40 — the 2nd from the end.

Pseudocode

function nth_from_end(head, n):
    fast = head
    slow = head

    // advance fast by n steps
    for i = 0 to n-1:
        if fast is null: return null   // n > list length
        fast = fast.next

    // move both until fast reaches null
    while fast is not null:
        fast = fast.next
        slow = slow.next

    return slow                        // slow is nth from end

Common Pitfalls

1. Off-by-one: is it 1-indexed or 0-indexed?

Most problems define "1st from end" as the last node. Make sure fast advances exactly n steps, not n−1 or n+1.

2. Not handling n > length

If fast becomes null before advancing n steps, n is larger than the list. Return null or handle the error.

3. Confusing with "remove nth from end"

To remove the nth from end, you need slow to stop one node before the target. Use a dummy head or advance fast by n+1.

What You Learned

Key Takeaways

The two-pointer gap technique: create a fixed gap between two pointers to find positions relative to the end.

This is a specific case of the fast/slow pointer family, which also includes cycle detection and finding midpoints.

Single-pass solutions are often possible by maintaining relationships between pointers.
