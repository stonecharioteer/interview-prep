EXERCISE #104

Trees: Find Maximum Value

Trees Beginner
Prerequisites
  • #103 preorder traversal — recursive tree traversal pattern

Why Find the Maximum?

Use Cases

Decision trees: Finding the highest-scoring leaf tells you the best outcome.

Game trees: The maximizing player picks the child with the highest value.

Foundation: This is the same recursive pattern used for sum, min, height, and many other tree aggregations.

What New Concept Does This Teach?

You learn the recursive aggregation pattern: visit a node, recurse into left and right subtrees, and combine the results. For max, you return the largest of node.val, max(left), and max(right). The base case returns negative infinity (or None).

The Approach

Recursive Max

At each node, recursively find the max of the left subtree and the max of the right subtree. The answer for this subtree is the largest of the three: the node's own value, the left max, and the right max.

Base case: if the node is null, return -Infinity.

Time & Space Complexity

Time: O(n) — every node is visited exactly once.

Space: O(h) — recursion stack depth equals tree height (O(log n) balanced, O(n) worst case).

Speed

Pseudocode

function tree_max(node):
    if node is null:
        return -Infinity
    left_max = tree_max(node.left)
    right_max = tree_max(node.right)
    return max(node.val, left_max, right_max)

Common Pitfalls

1. Wrong base case

Returning 0 for a null node is wrong if the tree contains negative values. Always return -Infinity (or the language equivalent) so that any real node value beats it.

2. Forgetting to compare the node itself

The max might be at the current node, not in either subtree. Always include node.val in the comparison.

What You Learned

Key Takeaways

The recursive aggregation pattern: recurse left, recurse right, combine with current node.

Use -Infinity as the base case for max operations on trees.

This same pattern adapts to min, sum, height, and more.
