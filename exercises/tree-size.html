Trees: Size (Node Count)

Trees Beginner
Prerequisites
  • #66 tree node — defining a binary tree node
  • #53 preorder traversal — visiting nodes recursively

Why Tree Size?

Use Cases

Balancing checks: Knowing subtree sizes lets you detect imbalanced trees (AVL, red-black).

Order-statistic trees: Finding the k-th smallest element requires knowing subtree sizes.

Foundation for recursion on trees: Size is the simplest "compute something for the whole tree" problem. If you can write size, you can write height, sum, max, etc.

What New Concept Does This Teach?

This is the purest example of post-order aggregation: compute the answer for both subtrees first, then combine with the current node. The pattern is: size(node) = 1 + size(left) + size(right). This same structure applies to height, sum, diameter, and many other tree problems.

How It Works

The Algorithm

Base case: if node is null, return 0.

Recurse: compute size(left) and size(right).

Combine: return 1 + size(left) + size(right).

Time & Space Complexity

Time: O(n) — every node is visited exactly once.

Space: O(h) — recursion stack depth equals the tree height. O(log n) for balanced, O(n) for skewed.

Speed

Pseudocode

function size(node):
    if node is null:
        return 0
    left_size = size(node.left)
    right_size = size(node.right)
    return 1 + left_size + right_size

Walkthrough

Computing the size of this tree:

Tree structure

       10
      /  \
     5    15
    / \     \
   3   7    20

Recursive computation

size(3)  = 1 + 0 + 0 = 1
size(7)  = 1 + 0 + 0 = 1
size(5)  = 1 + size(3) + size(7) = 1 + 1 + 1 = 3
size(20) = 1 + 0 + 0 = 1
size(15) = 1 + 0 + size(20) = 1 + 0 + 1 = 2
size(10) = 1 + size(5) + size(15) = 1 + 3 + 2 = 6

Common Pitfalls

1. Forgetting the +1 for the current node

A common mistake is returning size(left) + size(right) without adding 1. Each node contributes 1 to the total count.

2. Forgetting the null base case

Without if node is null: return 0, you will get a null-pointer error when reaching a leaf's child.

What You Learned

Key Takeaways

Post-order aggregation: compute children first, then combine — the fundamental pattern for tree computations.

1 + left + right is the template for size, and variations give height (1 + max(left, right)), sum (val + left + right), etc.

O(n) time — you must visit every node to count it.
