Why Quick Sort?

Use Cases

In-place sorting: Unlike merge sort, quicksort needs only O(log n) extra space for the recursion stack — no temporary arrays.

Cache-friendly: Quicksort works on contiguous memory, making it faster in practice than merge sort on arrays despite the same O(n log n) average.

Standard library default: Most language runtimes (C qsort, Java Arrays.sort for primitives) use quicksort or its variants.

What New Concept Does This Teach?

Quick sort teaches partitioning: choosing a pivot element and rearranging the array so that all elements smaller than the pivot are on the left and all larger elements are on the right. After partitioning, the pivot is in its final sorted position. Recurse on the two sides. The key insight is that partition does O(n) work and, on average, halves the problem — giving O(n log n) total.

How It Works

The Algorithm

Choose a pivot: Pick an element (last element in Lomuto, median-of-three in practice).

Partition: Rearrange so elements ≤ pivot are left, elements > pivot are right. Place pivot in its final position.

Recurse: Quicksort the left sub-array and the right sub-array.

Base case: sub-array of 0 or 1 elements is already sorted.

Time & Space Complexity

Time: O(n log n) average — each partition does O(n) work and on average halves the problem.

Time: O(n²) worst case — when the pivot is always the smallest or largest element (already sorted input with naive pivot).

Space: O(log n) — recursion stack depth. O(n) in worst case.

Pseudocode

function quick_sort(arr, lo, hi):
    if lo < hi:
        pivot_idx = partition(arr, lo, hi)
        quick_sort(arr, lo, pivot_idx - 1)
        quick_sort(arr, pivot_idx + 1, hi)

function partition(arr, lo, hi):
    pivot = arr[hi]          // choose last element
    i = lo - 1               // boundary of ≤ pivot region
    for j = lo to hi - 1:
        if arr[j] <= pivot:
            i++
            swap arr[i], arr[j]
    swap arr[i + 1], arr[hi] // place pivot in final spot
    return i + 1

Common Pitfalls

1. Worst-case pivot selection

Always picking the first or last element as pivot gives O(n²) on already-sorted input. Use median-of-three or random pivot to avoid this.

2. Not handling equal elements

When many elements equal the pivot, Lomuto partition degrades. Use three-way partition (Dutch National Flag) for arrays with many duplicates.

3. Stack overflow on large inputs

Worst-case recursion depth is O(n). Use tail-call optimization: always recurse on the smaller partition first, and loop on the larger one.

What You Learned

Key Takeaways

Partition is the core operation: one pass places the pivot in its final position.

O(n log n) average, O(n²) worst — pivot choice matters. Randomized pivot gives expected O(n log n).

In-place — quicksort uses O(log n) extra space vs. merge sort's O(n).

Not stable — equal elements may be reordered. Use merge sort when stability is required.
