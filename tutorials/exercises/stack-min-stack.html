EXERCISE #54

Stack: Min Stack (O(1) getMin)

Stacks Intermediate
Prerequisites
  • #14 Stack: Define — understanding push, pop, and stack fundamentals

What You Will Learn

This exercise teaches the auxiliary data structure pattern — maintaining extra state alongside your primary data structure to answer queries faster. Instead of scanning the entire stack for the minimum (O(n)), you keep a parallel "min tracker" stack that always knows the current minimum in O(1).

The Problem

Definition

Design a stack that supports push, pop, peek, and getMin — all in O(1) time. The getMin operation returns the smallest element currently in the stack without removing anything.

Why Is This Useful?

Real-World Use Cases

Stream processing: Track the running minimum of a data stream without rescanning.

Trading systems: Real-time minimum price tracking as trades are pushed/popped.

Design pattern: The "auxiliary structure" idea applies broadly — e.g., maintaining a max alongside a stack, or tracking frequencies.

Key Insight

Keep two stacks: the main stack and a min stack. The min stack's top always holds the minimum value of all elements currently in the main stack. When you push, also push onto the min stack if the new value is ≤ the current min. When you pop, also pop from the min stack if the popped value equals the current min.

Time & Space Complexity

push: O(1) — constant-time push on both stacks.

pop: O(1) — constant-time pop, conditional pop from min stack.

getMin: O(1) — just peek at the min stack.

Space: O(n) — worst case the min stack holds all n elements.

Speed

Pseudocode

structure MinStack:
    main = new Stack()
    mins = new Stack()

    function push(value):
        main.push(value)
        if mins.is_empty() or value <= mins.peek():
            mins.push(value)

    function pop():
        value = main.pop()
        if value == mins.peek():
            mins.pop()
        return value

    function getMin():
        return mins.peek()

    function peek():
        return main.peek()

Walkthrough

Tracing push 5, 3, 7, 2, 8

push(5): main=[5]       mins=[5]       min=5
push(3): main=[5,3]     mins=[5,3]     min=3  (3≤5, push to mins)
push(7): main=[5,3,7]   mins=[5,3]     min=3  (7>3, skip mins)
push(2): main=[5,3,7,2] mins=[5,3,2]   min=2  (2≤3, push to mins)
push(8): main=[5,3,7,2,8] mins=[5,3,2] min=2  (8>2, skip mins)

pop():   returns 8. 8!=2, mins unchanged. min=2
pop():   returns 2. 2==2, pop mins too.   min=3
pop():   returns 7. 7!=3, mins unchanged. min=3
pop():   returns 3. 3==3, pop mins too.   min=5
pop():   returns 5. 5==5, pop mins too.   empty!

Common Pitfalls

1. Using strict less-than instead of less-than-or-equal

If you push the same minimum value twice (e.g., push 3, push 3), you must push to the min stack both times. Use ≤ not <.

What You Learned

Key Takeaways

Auxiliary structure pattern: Maintaining extra state to answer queries in O(1) is a powerful technique.

Space-time tradeoff: We use O(n) extra space to make getMin O(1) instead of O(n).

Synchronization: The auxiliary structure must stay in sync with the main structure through every push and pop.
