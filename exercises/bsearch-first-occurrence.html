Binary Search: Find First Occurrence

Binary Search Intermediate
Prerequisites
  • #37 binary_search — basic binary search

Why Find First Occurrence?

Use Cases

Database range queries: Finding the start of a range of matching records in a sorted index.

Finding the start of a run: In sorted data with duplicates, find where a particular value first appears.

Lower bound: Many standard libraries provide lower_bound / bisect_left, which is exactly this operation.

Counting occurrences: Combined with "find last occurrence," you can count how many times a value appears in O(log n).

What New Concept Does This Teach?

Standard binary search stops as soon as it finds a match. But what if there are duplicates? You need to find the leftmost match. The key modification: when you find the target, do not stop. Record the position and keep searching left (set hi = mid - 1). This teaches the critical idea that binary search can be modified to find boundaries, not just existence.

How It Works

The Algorithm

Same as binary search, but with one change:

When arr[mid] == target, save mid as a candidate result, then narrow the search to the left half by setting hi = mid - 1.

If a better (earlier) match exists, we will find it. If not, our saved candidate is the answer.

Time & Space Complexity

Time: O(log n) — standard binary search, just with a different stopping condition.

Space: O(1)

Speed

Pseudocode

function first_occurrence(arr, target):
    lo = 0
    hi = length(arr) - 1
    result = -1

    while lo <= hi:
        mid = (lo + hi) / 2
        if arr[mid] == target:
            result = mid          // save candidate
            hi = mid - 1          // keep searching LEFT
        else if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1

    return result

Walkthrough

Find first occurrence of 2 in [1, 2, 2, 2, 3, 4, 5]:

Step by step

lo=0, hi=6, mid=3: arr[3]=2 == target! Save result=3. Set hi=2.
lo=0, hi=2, mid=1: arr[1]=2 == target! Save result=1. Set hi=0.
lo=0, hi=0, mid=0: arr[0]=1 < 2. Set lo=1.
lo=1, hi=0: loop ends.
Result: first occurrence at index 1.

Common Pitfalls

1. Stopping at the first match

The whole point is to NOT return immediately when you find the target. You must continue searching left to ensure you have the earliest occurrence.

2. Integer overflow in mid calculation

Use mid = lo + (hi - lo) / 2 instead of (lo + hi) / 2 to avoid overflow in languages with fixed-size integers.

What You Learned

Key Takeaways

Binary search is a template, not a single algorithm. You can modify the comparison logic for many problems.

Record and continue is a powerful pattern: save a candidate answer and keep narrowing.

Boundaries vs. existence: binary search finds boundaries in sorted data, not just whether an element exists.
