Recursion: Factorial with Memoization

Recursion Beginner
Prerequisites
  • #16 Factorial — basic recursion with base case and recursive case

What You Will Learn

This exercise introduces memoization — caching the results of function calls so that repeated calls with the same arguments return instantly. You will see how a memo table stores previously computed factorials and how a second call to factorial(3) skips all recursion by looking up the cached answer.

What is Memoization?

Definition

Memoization is an optimization technique where you store the results of expensive function calls in a cache (often a dictionary or array). Before computing, you check the cache. If the result is already there, return it immediately. Otherwise, compute it, store it, and return it.

Why Memoize Factorial?

Plain factorial does not have overlapping subproblems (each call is unique on the way down). But if you call factorial(5) and later factorial(3), the memoized version returns the cached result for 3! instantly. This pattern becomes essential in dynamic programming where subproblems genuinely overlap (Fibonacci, knapsack, etc.).

Use Cases

Where Memoization Appears

Dynamic programming foundation: Memoization is the “top-down” approach to DP. Every DP problem can be solved with recursion + memo.

Overlapping subproblems: Fibonacci, coin change, longest common subsequence — all benefit enormously from memoization.

API/database caching: The same principle applies at the system level: cache expensive queries to avoid recomputation.

Time & Space Complexity

First call factorial(n): O(n) — same as plain recursion, but results are cached.

Subsequent calls for cached values: O(1) — direct lookup in the memo table.

Space: O(n) — call stack + memo table.

Speed

Pseudocode

memo = {}   // shared cache

function factorial(n):
    if n in memo:
        return memo[n]         // cache hit!
    if n <= 1:
        result = 1
    else:
        result = n * factorial(n - 1)
    memo[n] = result           // store in cache
    return result

Walkthrough

Step by step: factorial(5) then factorial(3)

First call: factorial(5)
  factorial(5) → not cached, recurse
  factorial(4) → not cached, recurse
  factorial(3) → not cached, recurse
  factorial(2) → not cached, recurse
  factorial(1) → base case, return 1, memo[1]=1
  factorial(2) = 2*1 = 2, memo[2]=2
  factorial(3) = 3*2 = 6, memo[3]=6
  factorial(4) = 4*6 = 24, memo[4]=24
  factorial(5) = 5*24 = 120, memo[5]=120

Second call: factorial(3)
  factorial(3) → found in memo! Return 6 immediately.
  No recursion needed. O(1).

Common Pitfalls

1. Forgetting to check the cache before recursing

The cache check must come before the recursive call. Otherwise you still do all the work and memoization has no effect.

2. Not storing the result after computing

If you compute the answer but forget to save it in the memo, future calls will recompute from scratch.

3. Using memoization where there are no repeated calls

For a single factorial call, memoization adds overhead without benefit. It shines when the same function is called multiple times with overlapping inputs.

What You Learned

Key Takeaways

Memoization = caching: Store results of function calls. Check the cache first. Compute only if not cached.

O(1) for cached calls: Once a value is computed, all future lookups are instant.

Foundation for DP: Memoization is the top-down approach to dynamic programming. Master it and DP becomes much easier.
