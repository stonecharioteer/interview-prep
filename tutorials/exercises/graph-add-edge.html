Graph: Add Edge

Graph Beginner
Required Learning

The Problem

Definition

Implement add_edge(u, v) to add an edge between vertices u and v in a graph represented as an adjacency list. Handle both directed and undirected graphs.

Real-World: Social Network

When two people become friends on a social network, that's an undirected edge — both can see each other. When you follow someone on Twitter, that's a directed edge — you see their tweets, but they don't automatically see yours.

Directed vs Undirected

The Key Difference

Directed: add_edge(u, v) adds v to u's neighbor list only. The edge goes from u to v, not the reverse.

Undirected: add_edge(u, v) adds v to u's list AND u to v's list. The connection goes both ways.

The Algorithm

class Graph:
    def __init__(self, directed=False):
        self.adj = {}          # vertex → list of neighbors
        self.directed = directed

    def add_vertex(self, v):
        if v not in self.adj:
            self.adj[v] = []

    def add_edge(self, u, v, weight=None):
        self.add_vertex(u)
        self.add_vertex(v)

        if weight is not None:
            self.adj[u].append((v, weight))
            if not self.directed:
                self.adj[v].append((u, weight))
        else:
            self.adj[u].append(v)
            if not self.directed:
                self.adj[v].append(u)

Complexity

Time: O(1) — appending to a list is constant time.

Space: O(1) per edge — one list entry (two for undirected).

Walkthrough

Building an Undirected Graph

g = Graph(directed=False)
g.add_edge("A", "B")    → adj = {A: [B], B: [A]}
g.add_edge("A", "C")    → adj = {A: [B, C], B: [A], C: [A]}
g.add_edge("B", "C")    → adj = {A: [B, C], B: [A, C], C: [A, B]}

Building a Directed Graph

g = Graph(directed=True)
g.add_edge("A", "B")    → adj = {A: [B], B: []}
g.add_edge("A", "C")    → adj = {A: [B, C], B: [], C: []}
g.add_edge("B", "C")    → adj = {A: [B, C], B: [C], C: []}

Note: C has no outgoing edges, even though edges point TO it.

Weighted Edges

When Edges Have Costs

For algorithms like Dijkstra, edges carry weights (distances, costs, times). Store them as tuples: (neighbor, weight) instead of just neighbor.

g.add_edge("NYC", "LA", weight=2800)
g.add_edge("NYC", "CHI", weight=790)
→ adj = {NYC: [(LA,2800), (CHI,790)], LA: [(NYC,2800)], CHI: [(NYC,790)]}

Common Pitfalls

1. Forgetting to add both directions

For undirected graphs, always add the reverse edge too. Missing this is the #1 bug in graph problems.

2. Not creating vertices first

If u or v doesn't exist in the adjacency list, you'll get a KeyError. Always ensure both vertices exist before adding the edge.

3. Duplicate edges

Calling add_edge(A, B) twice creates a multigraph (two edges between A and B). If you don't want duplicates, check before appending, or use a set instead of a list.
