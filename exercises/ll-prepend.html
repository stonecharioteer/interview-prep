Linked Lists: Prepend to Start

Linked Lists Beginner

New Concept: O(1) Insertion at Head

Append requires traversing the entire list to find the tail — O(n). Prepend is O(1) because you always have direct access to the head. Just create a new node, point its next to the current head, and update the head pointer.

This is a key advantage of linked lists over arrays, where inserting at the beginning requires shifting all elements — O(n).

Use Cases

Stack implementation: Push onto the front of a linked list — O(1) push and pop.

Undo history: Most recent action goes to the front for quick access.

Building lists in reverse: Reading items and prepending builds the list in reverse order.

Time & Space Complexity

Time: O(1) — no traversal needed. Constant time regardless of list size.

Space: O(1) — one new node.

Pseudocode

function prepend(head, value):
    new_node = create Node(value)
    new_node.next = head       // point new node to current head
    return new_node            // new_node is the new head

Contrast: Append vs. Prepend

Append:  traverse to tail, link at end   — O(n)
Prepend: link at front, update head      — O(1)

For arrays it's reversed:
Append:  add at end (amortized)          — O(1)
Prepend: shift all elements right        — O(n)

What You Learned

Key Takeaways

O(1) head insertion is a core advantage of linked lists over arrays.

The operation is simple: create, point, update head. No traversal, no shifting.

Linked lists are ideal for stack-like (LIFO) access patterns because of this.
