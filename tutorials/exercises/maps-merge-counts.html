Why Merge Count Maps?

The Problem

You have two frequency maps and you want to combine them into a single map where each key's count is the sum of its counts in both maps. If a key appears in only one map, its count carries over unchanged.

Real-World Use Cases

Distributed systems: Each server counts word frequencies in its shard of data. Merge all partial counts into a global result.

MapReduce: The "reduce" step often merges partial aggregations from parallel mappers.

Multi-file analysis: Count errors per type in each log file, then merge across all files.

Team scoring: Merge individual scores from multiple rounds of a competition.

What This Exercise Teaches

New Concept: Combining Maps

In #51, you built a map from a flat list. Now you learn to combine two maps, handling the three cases:

Key only in A: copy it to the result.

Key only in B: copy it to the result.

Key in both A and B: sum the counts.

This is a stepping stone to more general "merge" operations (union, intersection, difference) on maps and sets.

Complexity

Time: O(m + n) — where m and n are the sizes of the two maps. You visit each key once.

Space: O(m + n) — the result map contains all unique keys from both inputs.

Speed

Pseudocode

function merge_counts(map_a, map_b):
    result = copy of map_a

    for each (key, count) in map_b:
        existing = get_or_default(result, key, 0)
        result[key] = existing + count

    return result

Walkthrough

Merging two word counts

map_a = {"the": 5, "cat": 3, "sat": 2}
map_b = {"the": 3, "dog": 4, "sat": 1}

Step 1: Copy all of map_a into result.
  result = {"the": 5, "cat": 3, "sat": 2}

Step 2: Process map_b key "the":
  result["the"] = 5 + 3 = 8

Step 3: Process map_b key "dog":
  "dog" not in result, so result["dog"] = 0 + 4 = 4

Step 4: Process map_b key "sat":
  result["sat"] = 2 + 1 = 3

Final: {"the": 8, "cat": 3, "sat": 3, "dog": 4}

Common Pitfalls

1. Mutating the input map

If you use map_a as the result directly, you modify the caller's data. Always work on a copy if you need to preserve the originals.

2. Only iterating over one map

If you only iterate over map_b's keys and check map_a, you miss keys that exist only in map_a. The copy-then-iterate approach avoids this.

What You Learned

Key Takeaways

Merging maps requires handling three cases: key in A only, B only, or both.

The copy-then-iterate pattern handles all cases cleanly in O(m + n).

This pattern is the foundation for distributed aggregation and MapReduce.
