What's New Here

Previous exercises searched for one value. Two Sum asks: given an array and a target, find two elements whose sum equals the target. The brute-force approach checks every pair — O(n²). The hash map approach does it in O(n) by remembering what you've already seen.

Why Two Sum?

Real-World Use Cases

Financial transactions: Find two transactions that sum to a specific amount (e.g., reconciliation).

Complementary pairs: Matching supply and demand, pairing items with complementary properties.

Interview classic: The most frequently asked coding interview question — tests hash map intuition.

The Algorithm

Hash Map Approach (O(n))

For each element num at index i, compute the complement = target - num. Check if the complement is already in the hash map:

• If yes: return the stored index and i.

• If no: store num → i in the hash map and move on.

You only pass through the array once.

Time & Space Complexity

Brute force: O(n²) time, O(1) space — check every pair.

Hash map: O(n) time, O(n) space — one pass, trading space for speed.

Speed

Pseudocode

function two_sum(arr, target):
    seen = {}                        // hash map: value → index
    for i from 0 to len(arr) - 1:
        complement = target - arr[i]
        if complement in seen:
            return [seen[complement], i]
        seen[arr[i]] = i
    return []                        // no pair found

Walkthrough

Find two numbers in [2, 7, 11, 15] that sum to 9:

Step by step

i=0: num=2, complement=9-2=7. seen={}. 7 not in seen. Store {2:0}.
i=1: num=7, complement=9-7=2. seen={2:0}. 2 IS in seen! Return [0, 1].

Answer: indices [0, 1] — values 2 + 7 = 9.

Brute Force vs Hash Map

Why Not Just Use Two Loops?

The brute force checks every pair: for each element, scan all elements after it. That's n * (n-1) / 2 comparisons = O(n²).

With 10,000 elements: brute force = ~50,000,000 ops. Hash map = ~10,000 ops. The hash map is ~5,000x faster because each lookup is O(1) on average.

Common Pitfalls

1. Using the same element twice

Check the complement before storing the current element. This prevents matching an element with itself (e.g., target=6, arr=[3,...] — you'd wrongly match 3+3).

2. Returning values instead of indices

The classic problem asks for indices, not values. Store the index in the map, not just a boolean.

What You Learned

Key Takeaways

Hash maps trade space for time — O(n) space buys you O(n) time instead of O(n²).

Complement pattern — "what do I need?" is a powerful hash map idiom.

One-pass solution — you can build and query the map simultaneously.
