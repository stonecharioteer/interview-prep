Sorting: Insertion Sort

Sorting Beginner
Prerequisites
  • #31 selection_sort — sorted/unsorted partition concept

Why Insertion Sort?

Use Cases

Nearly-sorted data: Insertion sort is O(n) on nearly-sorted arrays — it only shifts elements that are out of place. This makes it ideal when data arrives mostly in order.

Online sorting: You can sort elements as they arrive, one at a time. No need to see the whole array upfront.

Small arrays: Many real-world sort implementations (like Timsort) switch to insertion sort for small subarrays because its low overhead beats O(n log n) algorithms below ~20 elements.

Card sorting analogy: This is exactly how most people sort a hand of cards — pick up each card and slide it into the correct position among the ones already in your hand.

What New Concept Does This Teach?

Insertion sort teaches maintaining a sorted subarray by inserting each new element in its correct position. Unlike selection sort (which searches for the minimum), insertion sort picks the next unsorted element and shifts larger elements right to make room for it. This "shift and insert" pattern appears in many algorithms.

How It Works

The Algorithm

Start with the first element as a sorted subarray of size 1. For each subsequent element (the "key"), compare it with elements in the sorted portion from right to left. Shift each larger element one position to the right. Insert the key into the gap.

Time & Space Complexity

Time: O(n²) worst case (reverse-sorted array — every element must shift all the way left).

Time: O(n) best case (already sorted — inner loop never executes).

Space: O(1) — in-place sorting.

Speed

Pseudocode

function insertion_sort(arr):
    for i from 1 to length(arr) - 1:
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]    // shift right
            j = j - 1
        arr[j + 1] = key           // insert

Walkthrough

Let's trace sorting [12, 11, 13, 5, 6]:

Step by step

i=1: key=11. Compare with 12: shift 12 right.
  Insert 11 at index 0 → [11,12,13,5,6]
i=2: key=13. Compare with 12: 12 ≤ 13, stop.
  Already in place → [11,12,13,5,6]
i=3: key=5. Compare with 13,12,11: shift all right.
  Insert 5 at index 0 → [5,11,12,13,6]
i=4: key=6. Compare with 13,12,11: shift all right.
  Compare with 5: 5 ≤ 6, stop.
  Insert 6 at index 1 → [5,6,11,12,13]

Common Pitfalls

1. Off-by-one in insertion position

After the while loop, the key goes at j + 1, not j. The loop stops when arr[j] ≤ key, so the key belongs one position to the right of j.

2. Confusing shift with swap

Insertion sort shifts elements, not swaps them. You save the key, move elements right, then place the key. This is one write per shift, not two writes per swap.

What You Learned

Key Takeaways

Shift-and-insert is more efficient than swap-based approaches when the sorted portion is large.

Adaptive: Performance scales with how unsorted the data is, making it ideal for "almost sorted" inputs.

Stable: Equal elements maintain their original relative order.

Online: Can sort a stream of data as it arrives.
