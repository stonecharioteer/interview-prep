What's New Here

This exercise introduces the conditional counting pattern: an accumulator that only increments when a condition is met. It combines the accumulator idea from sum with the equality check from contains, but unlike contains, it does not stop early — you must scan the entire array to get an accurate count.

Why Count Occurrences?

Real-World Use Cases

Frequency analysis: How many times does each word appear in a document?

Histogram building: Count how many data points fall in each bucket.

Voting/polling: Count how many votes each candidate received.

Quality control: How many defective items in a batch?

The Algorithm

How It Works

Initialize a counter to 0. Walk through every element: if it equals the target, increment the counter. Return the counter at the end.

Notice: no early termination here. Even after finding matches, there may be more later in the array.

Time & Space Complexity

Time: O(n) — must check every element.

Space: O(1) — one counter variable.

Speed

Walkthrough

Let's count occurrences of 3 in [3, 7, 3, 2, 3, 9, 3]:

Step by step

Initialize: count = 0

Index 0: 3 == 3? Yes! count = 1
Index 1: 7 == 3? No.  count = 1
Index 2: 3 == 3? Yes! count = 2
Index 3: 2 == 3? No.  count = 2
Index 4: 3 == 3? Yes! count = 3
Index 5: 9 == 3? No.  count = 3
Index 6: 3 == 3? Yes! count = 4

Result: 3 appears 4 times.

Pseudocode

function count_of(arr, target):
    count = 0
    for i from 0 to len(arr) - 1:
        if arr[i] == target:
            count = count + 1
    return count

Common Pitfalls

1. Stopping early

Unlike contains, you cannot stop at the first match. The target may appear more times later in the array.

2. Off-by-one in the count

Initialize the counter to 0, not 1. Only increment when a match is found.

What You Learned

Key Takeaways

Conditional accumulation — only update the accumulator when a condition holds.

This pattern generalizes: count items matching any predicate, not just equality.

No early exit — you need the complete picture.
