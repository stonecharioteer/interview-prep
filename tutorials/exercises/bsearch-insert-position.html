Binary Search: Search Insert Position

Binary Search Intermediate
Prerequisites
  • #38 first_occurrence — modified binary search with boundary finding

Why Search Insert Position?

Use Cases

Maintaining sorted order: When inserting into a sorted array (or list), you need to know where the new element belongs.

bisect / lower_bound: Python's bisect.bisect_left, C++'s lower_bound, and Java's Collections.binarySearch all do essentially this.

Ranking: The insert position tells you how many elements are smaller than the target — its rank in the sorted order.

Interval queries: Finding where a value falls in sorted breakpoints (tax brackets, grade boundaries, etc.).

What New Concept Does This Teach?

This teaches you that binary search can find the position where an element would be inserted to maintain sorted order, even when the element is not in the array. The key insight: when the loop ends, lo points to the insert position. This is because lo has been pushed past all elements less than the target.

How It Works

The Algorithm

Run standard binary search. If the target is found, return its index. If not found, return lo — this is where the target would need to be inserted.

Why lo? When the loop ends (lo > hi), lo is at the first position where all elements to the left are smaller than the target.

Time & Space Complexity

Time: O(log n)

Space: O(1)

Pseudocode

function search_insert_position(arr, target):
    lo = 0
    hi = length(arr) - 1

    while lo <= hi:
        mid = (lo + hi) / 2
        if arr[mid] == target:
            return mid            // found it
        else if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1

    return lo                     // insert position

Walkthrough

Example 1: Target not in array

Find insert position for 4 in [1, 3, 5, 6]:

lo=0, hi=3, mid=1: arr[1]=3 < 4. lo=2.
lo=2, hi=3, mid=2: arr[2]=5 > 4. hi=1.
lo=2, hi=1: loop ends. Insert at lo=2.
Result: [1, 3, [4], 5, 6] — 4 goes at index 2.

Example 2: Target in array

Find insert position for 5 in [1, 3, 5, 6]:

lo=0, hi=3, mid=1: arr[1]=3 < 5. lo=2.
lo=2, hi=3, mid=2: arr[2]=5 == 5. Return 2.
Result: 5 is already at index 2.

Example 3: Target beyond all elements

Find insert position for 7 in [1, 3, 5, 6]:

Search narrows until lo=4, hi=3. Return lo=4.
Result: 7 goes at the end (index 4).

Common Pitfalls

1. Returning hi instead of lo

When the loop ends, lo is the correct insert position, not hi. At termination, lo = hi + 1, and lo is where the target belongs.

2. Not handling edge cases

Target smaller than all elements: returns 0 (insert at beginning). Target larger than all: returns n (insert at end). Both are handled naturally by the algorithm.

What You Learned

Key Takeaways

lo after binary search is the insert position — the first index where arr[i] ≥ target.

bisect_left / lower_bound is the same algorithm — a foundational tool in every language's standard library.

Rank = insert position: the number of elements smaller than the target.

Binary search variants are small modifications of the same template. Mastering these three (first, last, insert) covers most interview binary search problems.
