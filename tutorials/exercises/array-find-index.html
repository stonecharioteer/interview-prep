Arrays: Find First Index

Arrays Beginner
Prerequisites
  • #4 contains — early termination pattern

What's New Here

contains tells you whether an element exists (true/false). This exercise teaches you to return the position (index) instead of just a boolean. The distinction between value and position is fundamental — many algorithms need to know where something is, not just that it exists. You also learn the convention of returning -1 (or a sentinel value) when the element is not found.

Why Find the Index?

Real-World Use Cases

Lookup tables: Find where a key lives so you can update its associated value.

Search results: Highlight the position of a match in text.

Insertion point: Find where an element is to decide where to insert relative to it.

Swap operations: You need the index to swap or move an element.

The Algorithm

How It Works

Scan left to right. When you find the target, return the current index immediately (early termination). If the loop ends without a match, return -1 to signal "not found."

Time & Space Complexity

Time: O(n) worst case, O(1) best case.

Space: O(1) — no extra storage.

Walkthrough

Find the index of 16 in [4, 8, 15, 16, 23, 42]:

Step by step

Index 0: 4 == 16? No.
Index 1: 8 == 16? No.
Index 2: 15 == 16? No.
Index 3: 16 == 16? Yes! Return 3.

Pseudocode

function find_index(arr, target):
    for i from 0 to len(arr) - 1:
        if arr[i] == target:
            return i           // return the position
    return -1                  // sentinel: not found

Common Pitfalls

1. Returning the value instead of the index

return arr[i] gives you the value (which you already know — it's the target). You want return i.

2. Forgetting the not-found case

Always handle the case where the target doesn't exist. Returning -1 is the most common convention, but some languages use null or raise an error.

3. Finding last vs. first

This returns the first occurrence. If you need the last, scan right-to-left or scan the entire array and keep updating.

What You Learned

Key Takeaways

Position vs. value — knowing where something is enables further operations.

Sentinel values — -1 communicates "not found" without exceptions.

Same early-termination pattern as contains, different return type.
