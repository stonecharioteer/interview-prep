Linked Lists: Insert at Index

Linked Lists Intermediate
Prerequisites
  • #32 remove_first — pointer rewiring with prev/curr

New Concept: Navigate Then Splice

This exercise combines two skills: (1) navigating to a position (from get_kth) and (2) splicing in a new node (pointer manipulation from remove_first, but in reverse).

To insert at index k, walk to the node at index k-1 (the predecessor), create the new node, set new_node.next = predecessor.next, then set predecessor.next = new_node. Order matters — if you set predecessor.next first, you lose the reference to the rest of the list.

Time & Space Complexity

Time: O(k) — traverse to position k.

Space: O(1) — one new node.

Pseudocode

function insert_at_index(head, index, value):
    new_node = create Node(value)
    if index == 0:
        new_node.next = head
        return new_node          // new head
    curr = head
    for i from 0 to index - 2:
        if curr is null:
            error "index out of bounds"
        curr = curr.next
    if curr is null:
        error "index out of bounds"
    new_node.next = curr.next    // point new node to successor
    curr.next = new_node         // link predecessor to new node
    return head

Common Pitfalls

1. Order of pointer updates

Always set new_node.next BEFORE curr.next. Otherwise you lose the rest of the list.

2. Index 0 is a special case

Inserting at index 0 is just prepend — no predecessor to navigate to.

What You Learned

Key Takeaways

Navigate + splice: Walk to the predecessor, then rewire pointers.

Order matters: Set new_node.next first, then predecessor.next.

This is O(k) for the traversal, but the actual insertion is O(1) once you are at the right position.
