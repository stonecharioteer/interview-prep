Kadane's Algorithm: Maximum Subarray Sum

The Problem

Maximum Subarray Sum

Given an array of integers (possibly negative), find the contiguous subarray with the largest sum. For example: 

[-2, 1, -3, 4, -1, 2, 1, -5, 4]
                   ^-----------^
                   subarray [4, -1, 2, 1] has sum = 6 (maximum)

This is one of the most classic dynamic programming / greedy problems in computer science, known as Kadane's Algorithm (1984).

Complexity Comparison

Brute force: O(n²) — check every subarray start/end pair.

Kadane's algorithm: O(n) — single pass through the array.

Space: O(1) — just two variables.

For n = 1,000,000: brute force = 1012 ops. Kadane = 106 ops. A million times faster.

The Key Insight

Kadane's Insight

At each position i, you face a simple choice: should the maximum subarray ending here include the previous subarray, or start fresh from the current element? 

current_sum = max(arr[i], current_sum + arr[i])

If the running sum plus arr[i] is worse than just arr[i] alone, the previous subarray was dragging us down. Drop it and start over.

Real-World Analogy: Daily Profits

Imagine tracking daily profits/losses for a business. You want to find the best consecutive streak. Each day, you ask: "Am I better off continuing my current streak, or should I mentally reset and start counting from today?" If your cumulative profit has gone negative, any new gains are better counted from scratch.

Walkthrough

Array: [-2, 1, -3, 4, -1, 2, 1, -5, 4]

Step-by-Step Trace

i=0: arr[i]=-2  current=max(-2, 0+(-2))=-2   max_sum=-2
i=1: arr[i]= 1  current=max(1, -2+1)=1       max_sum=1
i=2: arr[i]=-3  current=max(-3, 1+(-3))=-2   max_sum=1
i=3: arr[i]= 4  current=max(4, -2+4)=4       max_sum=4   ← reset! start fresh at 4
i=4: arr[i]=-1  current=max(-1, 4+(-1))=3    max_sum=4
i=5: arr[i]= 2  current=max(2, 3+2)=5        max_sum=5
i=6: arr[i]= 1  current=max(1, 5+1)=6        max_sum=6   ← new best!
i=7: arr[i]=-5  current=max(-5, 6+(-5))=1    max_sum=6
i=8: arr[i]= 4  current=max(4, 1+4)=5        max_sum=6

Answer: 6 (subarray [4, -1, 2, 1])

Pseudocode

def max_subarray_sum(arr):
    if len(arr) == 0:
        return 0

    current_sum = arr[0]
    max_sum = arr[0]

    for i in range(1, len(arr)):
        # Either extend the previous subarray or start fresh
        current_sum = max(arr[i], current_sum + arr[i])
        max_sum = max(max_sum, current_sum)

    return max_sum

Variant: Return the Subarray Itself

Track the start and end indices. When current_sum resets (i.e., arr[i] > current_sum + arr[i]), update the tentative start. When max_sum is updated, record the final start and current index as end.

Brute Force Comparison

O(n²) Approach

def max_subarray_brute(arr):
    max_sum = arr[0]
    for i in range(len(arr)):
        current = 0
        for j in range(i, len(arr)):
            current += arr[j]
            max_sum = max(max_sum, current)
    return max_sum

This checks every possible subarray. Kadane's eliminates the inner loop by recognizing that a negative running sum is never worth keeping.

Common Pitfalls

1. Initializing to 0 instead of arr[0]

If all elements are negative (e.g., [-3, -1, -2]), the answer is -1 (the least negative). Initializing max_sum = 0 would incorrectly return 0. Always initialize to the first element.

2. Empty array edge case

Decide what to return for an empty array. Common choices: 0, negative infinity, or raise an error. Document your choice.

3. Confusing subarray with subsequence

A subarray is contiguous (elements must be adjacent). A subsequence can skip elements. Kadane's solves the subarray problem. For maximum subsequence sum with positives, just sum all positive elements.
