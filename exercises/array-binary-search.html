Arrays: Binary Search

Arrays Intermediate
Prerequisites
  • #29 is_sorted — understanding sorted arrays and pairwise ordering

What's New Here

All previous search exercises used linear scan: check each element one by one, O(n). Binary search introduces divide and conquer — by looking at the middle element, you cut the search space in half with every step. This only works on sorted data, which is why is_sorted was a prerequisite. Searching a billion elements takes only ~30 steps instead of a billion.

Why Binary Search?

Real-World Use Cases

Dictionary lookup: Open to the middle, then narrow left or right — exactly binary search.

Finding values in sorted data: Any pre-sorted list or table can be searched in O(log n).

Database index lookups: B-trees use binary search at each node to locate records.

The Algorithm

How It Works

Maintain a search range [lo, hi]. Compute mid = (lo + hi) / 2. Compare arr[mid] with the target:

• If equal: found it! Return mid.

• If arr[mid] < target: the answer must be to the right. Set lo = mid + 1.

• If arr[mid] > target: the answer must be to the left. Set hi = mid - 1.

Repeat until lo > hi (range is empty = not found).

Time & Space Complexity

Time: O(log n) — each step halves the search space.

Space: O(1) — iterative version uses only a few variables.

Speed

Walkthrough

Search for 23 in [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]:

Step by step

lo=0, hi=9, mid=4: arr[4]=16. 16 < 23 → lo=5.
lo=5, hi=9, mid=7: arr[7]=56. 56 > 23 → hi=6.
lo=5, hi=6, mid=5: arr[5]=23. Found! Return 5.

Only 3 comparisons instead of 6 (linear scan).

Pseudocode

function binary_search(arr, target):
    lo = 0
    hi = len(arr) - 1
    while lo ≤ hi:
        mid = lo + (hi - lo) / 2     // integer division, avoids overflow
        if arr[mid] == target:
            return mid
        else if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1                          // not found

Common Pitfalls

1. Integer overflow in mid calculation

(lo + hi) / 2 can overflow if lo and hi are large. Safer: lo + (hi - lo) / 2.

2. Using on unsorted data

Binary search requires sorted input. On unsorted data it gives wrong results. Always sort first or verify with is_sorted.

3. Off-by-one in lo/hi updates

After checking mid, set lo = mid + 1 or hi = mid - 1. Setting lo = mid can cause an infinite loop when lo == mid.

4. Loop condition: ≤ not <

Use lo ≤ hi. Using lo < hi misses the case when the target is at the single remaining position where lo == hi.

What You Learned

Key Takeaways

Divide and conquer — halving the problem each step gives O(log n).

Precondition — data must be sorted.

The most important search algorithm — appears everywhere from databases to git bisect.
