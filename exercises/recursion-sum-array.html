Recursion: Sum Array

Recursion Beginner
Prerequisites
  • #16 Factorial — understanding base case and recursive case
  • #3 Array Sum — iterative sum of array elements

What You Will Learn

This exercise shows how to apply recursion to array problems. Instead of looping through the array, you handle one element and recursively process the rest. The array “shrinks by one” on each call until it is empty — the base case. This pattern is the foundation for divide-and-conquer algorithms on arrays.

The Recursive Approach

Shrink by One

To sum an array recursively: take the first element and add it to the sum of the rest. The “rest” is a smaller array, so eventually you reach an empty array (base case: sum is 0).

sum([3,1,4,1,5]) = 3 + sum([1,4,1,5]) = 3 + 1 + sum([4,1,5]) = ...

Use Cases

Where This Pattern Appears

Recursive vs iterative: Understanding when recursion is cleaner than a loop and when it is not.

Foundation for divide-and-conquer: Merge sort splits an array in half recursively. This exercise teaches the simpler “shrink by one” pattern first.

Functional programming: Languages like Haskell and Lisp process lists recursively by default (head + tail pattern).

Time & Space Complexity

Time: O(n) — one recursive call per element.

Space: O(n) — n frames on the call stack.

Speed

Pseudocode

function sum_array(arr, index):
    if index >= length of arr:    // base case: past the end
        return 0
    return arr[index] + sum_array(arr, index + 1)

Walkthrough

Step by step: sum([3, 1, 4, 1, 5])

Call stack builds up:
  sum([3,1,4,1,5], 0) = 3 + sum([3,1,4,1,5], 1)
  sum([3,1,4,1,5], 1) = 1 + sum([3,1,4,1,5], 2)
  sum([3,1,4,1,5], 2) = 4 + sum([3,1,4,1,5], 3)
  sum([3,1,4,1,5], 3) = 1 + sum([3,1,4,1,5], 4)
  sum([3,1,4,1,5], 4) = 5 + sum([3,1,4,1,5], 5)
  sum([3,1,4,1,5], 5) = 0   ← base case (index past end)

Call stack unwinds:
  5 + 0 = 5
  1 + 5 = 6
  4 + 6 = 10
  1 + 10 = 11
  3 + 11 = 14  ← final answer

Common Pitfalls

1. Off-by-one in the base case

The base case triggers when the index equals (or exceeds) the array length. Using > instead of >= can cause an out-of-bounds access.

2. Copying the array instead of passing an index

Creating a new sub-array on each call (e.g., arr[1:]) works but wastes O(n) time per call, making the total O(n²). Pass an index instead.

3. Forgetting that a loop is simpler here

For summing an array, a loop is cleaner and uses O(1) space. The recursive version is for learning the pattern, not for production code.

What You Learned

Key Takeaways

Shrink by one: Process one element, recurse on the rest. The array effectively shrinks by one each call.

Index-based recursion: Pass an index rather than slicing the array to keep each call O(1).

Recursive vs iterative: Both solve the problem, but recursion uses O(n) stack space while a loop uses O(1).
