Monotonic Stack: Next Smaller Element

Monotonic Stack Intermediate
Prerequisites
  • #77 valid_parens — using a stack to process elements in order

What's New Here

You already know how to use a stack for matching pairs. A monotonic stack takes it further: the stack maintains a specific ordering (increasing or decreasing) at all times. When a new element violates the order, you pop elements — and each popped element has just found its answer.

For next smaller element, we maintain an increasing stack (bottom to top). When we encounter a smaller element, we pop everything larger — those elements' "next smaller" is the current element.

Why Monotonic Stack?

Use Cases

Stock span: How many consecutive days had a price ≤ today's?

Histogram largest rectangle: Next smaller bar determines width limits.

Daily temperatures: How many days until a warmer temperature?

How It Works

Traverse left to right. For each element:
1. While the stack is not empty and stack.top() ≥ current: pop. The popped element's next smaller is current.
2. Push current (its index) onto the stack.
3. After the loop, remaining stack elements have no next smaller element (−1).

Time & Space Complexity

Time: O(n) — each element is pushed and popped at most once.

Space: O(n) — stack can hold all elements in worst case (sorted ascending).

Walkthrough

Find next smaller for [4, 8, 5, 2, 25]:

Step by step

i=0, val=4:  Stack empty. Push 4. Stack: [4]
i=1, val=8:  8 > 4, push. Stack: [4, 8]
i=2, val=5:  5 < 8, pop 8 → result[1] = 5. 5 > 4, push. Stack: [4, 5]
i=3, val=2:  2 < 5, pop 5 → result[2] = 2.
             2 < 4, pop 4 → result[0] = 2. Push 2. Stack: [2]
i=4, val=25: 25 > 2, push. Stack: [2, 25]

Remaining: pop 25 → result[4] = -1. pop 2 → result[3] = -1.

Result: [2, 5, 2, -1, -1]

Pseudocode

function next_smaller_element(arr):
    n = len(arr)
    result = [-1] * n
    stack = []                    // stores indices

    for i = 0 to n-1:
        while stack is not empty and arr[stack.top()] ≥ arr[i]:
            idx = stack.pop()
            result[idx] = arr[i]
        stack.push(i)

    return result                 // remaining stack entries stay -1

Common Pitfalls

1. Comparing values but storing indices

The stack stores indices so you can fill in the result array. Compare using arr[stack.top()], not the index itself.

2. Using > instead of ≥

Depending on the problem, duplicates matter. For strictly smaller, use ≥ in the pop condition. For smaller-or-equal, use >.

3. Confusing next smaller vs previous smaller

Next smaller: traverse left to right, pop when current is smaller. Previous smaller: traverse right to left (or left to right with different logic).

What You Learned

Key Takeaways

A monotonic stack maintains a sorted invariant, enabling O(n) solutions to "next greater/smaller" problems.

Each element is pushed once and popped once, so total work is O(n) even though there's a while loop inside the for loop.

This pattern is the foundation for histogram problems, stock span, and temperature problems.
