Stack: Define and Implement

Stacks Beginner
Prerequisites
  • #1 Arrays — understanding indexed collections

What You Will Learn

This exercise introduces the stack — the first abstract data type beyond arrays. You will learn the LIFO principle and how to implement a stack using an array. Stacks appear everywhere: your browser's back button, the undo feature in editors, and the function call mechanism in every programming language.

What is a Stack?

Definition

A stack is an abstract data type that follows the Last-In, First-Out (LIFO) principle. The last element added is the first one removed — like a stack of plates. You can only interact with the top of the stack.

Core Operations

push(value): Add an element to the top of the stack.

pop(): Remove and return the top element.

peek(): Look at the top element without removing it.

is_empty(): Check if the stack has no elements.

All four operations run in O(1) time.

Why Use a Stack?

Real-World Use Cases

Undo/Redo: Each action is pushed onto a stack. Undo pops the last action.

Browser back button: Each page visit is pushed. Back pops to the previous page.

Function call stack: When function A calls B, A's context is pushed. When B returns, A's context is popped and resumed.

Expression parsing: Compilers use stacks to evaluate mathematical expressions and match brackets.

Time & Space Complexity

push: O(1) — append to end of internal array.

pop: O(1) — remove from end of internal array.

peek: O(1) — read end of internal array.

Space: O(n) — proportional to number of elements stored.

Pseudocode

structure Stack:
    data = []    // internal array

    function push(value):
        data.append(value)       // add to end

    function pop():
        if is_empty():
            error "stack underflow"
        return data.remove_last() // remove from end

    function peek():
        if is_empty():
            error "stack is empty"
        return data[length - 1]   // look at end

    function is_empty():
        return length of data == 0

Implementing with an Array

Why Arrays Work

An array supports O(1) append and O(1) remove-from-end. Since a stack only ever touches its top (the end of the array), an array is a natural fit. The "top" of the stack is simply the last element of the array.

Walkthrough

Step by step: push 10, push 20, push 30, pop, pop, pop

push(10): stack = [10]          top = 10
push(20): stack = [10, 20]      top = 20
push(30): stack = [10, 20, 30]  top = 30
pop():    returns 30, stack = [10, 20]  top = 20
pop():    returns 20, stack = [10]      top = 10
pop():    returns 10, stack = []        empty!

Notice: elements come out in reverse order (30, 20, 10). That is LIFO.

Common Pitfalls

1. Pop on empty stack

Always check is_empty() before popping. Popping from an empty stack is an error called stack underflow.

2. Confusing LIFO with FIFO

A stack is LIFO (last in, first out). A queue is FIFO (first in, first out). They are different data structures for different problems.

What You Learned

Key Takeaways

LIFO principle: Last in, first out. The most recently added element is removed first.

Abstract data type: A stack defines behavior (push/pop/peek), not implementation. Arrays are just one way to build one.

O(1) everything: All stack operations are constant time.
