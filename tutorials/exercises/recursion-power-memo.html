Recursion: Power with Memoization

Recursion Intermediate
Prerequisites
  • #48 power(base, exp) — fast exponentiation by squaring
  • #17 factorial with memoization — caching concept

What's New Here

You already know fast exponentiation and memoization separately. Here we combine them. When you call power(2, 10) and later power(2, 5), the second call can reuse the cached subresult from the first. The cache turns repeated queries from O(log n) to O(1).

Why Memoize Power?

Use Cases

Repeated computations: In crypto or number theory, you often compute powers of the same base with different exponents. Shared sub-computations can be cached.

Dynamic programming preview: Memoization is the top-down approach to DP. Understanding it here prepares you for problems like coin change and longest subsequence.

Time & Space Complexity

First call: O(log n) — same as without memo.

Cached call: O(1) — instant lookup.

Space: O(log n) — cache stores at most log n intermediate results per base.

Pseudocode

memo = {}

function power_memo(base, exp):
    if exp == 0:
        return 1
    key = (base, exp)
    if key in memo:
        return memo[key]          // cache hit!
    if exp is even:
        half = power_memo(base, exp / 2)
        result = half * half
    else:
        result = base * power_memo(base, exp - 1)
    memo[key] = result            // store in cache
    return result

Common Pitfalls

1. Cache key must include both base and exp

power(2, 5) and power(3, 5) have different results. The key must be (base, exp), not just exp.

What You Learned

Key Takeaways

Memoization = caching recursive results to avoid redundant computation.

Combining optimizations: Fast exponentiation gives O(log n); memoization gives O(1) for repeated queries.

This is top-down DP — the same concept powers dynamic programming solutions.
